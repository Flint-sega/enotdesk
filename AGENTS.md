# EnotDesk

Portable remote support, self-hosted, AGPL-3.0: клиент помощи запускается без установки (Windows/macOS/Linux), передаёт одноразовые ID/пароль оператору через обычный чат, закрытие окна мгновенно завершает доступ. Оригинальное Electron+WebRTC-приложение, не форк RustDesk (ADR 0001).

## Current state
Рабочий MVP: attended-сеансы (ID/пароль → согласие клиента → видео WebRTC + ввод/чат/буфер/файлы по DataChannel), unattended-машины (onboarding-код → агент-служба, claim оператора с обязательной причиной и PIN-политикой, проверяемой сервером), браузерный оператор `/operator` без установки клиента, i18n ru/en на клиенте и серверных страницах. Терминал машины (v1, честные границы): DC-канал `term`, 1 терминал на машину, оболочка через пайпы child_process (node-pty нет, resize сохраняется на будущее), контекст исполнения помечается честно — Windows = `SYSTEM` (служба LocalSystem), Linux = консольный пользователь (`sudo -u`) или `service`, macOS = `launchctl asuser <uid>` или `service`; кольцевой буфер вывода 512 КБ с реплеем, таймаут простоя 5 мин. Toast на экран машины: `POST /machines/:id/toast` → выдача через машинный heartbeat → агент `showToast` (Windows WTSSendMessageW в активную сессию, Linux notify-send от консольного пользователя, macOS osascript), подтверждение агента ждёт оператор до 12 с, TTL запроса 60 с. Инвентарь машины: агент шлёт `{os, appVersion, uptimeSec, diskFreeGb}` с heartbeat'ом, сервер санитизирует allowlist'ом (≤4 КБ, мусор → прошлый инвентарь сохраняется), виден в UI машин. TOTP-2FA: включение по паролю + подтверждение первым кодом, 10 одноразовых резервных кодов (sha256), секрет шифруется AES-256-GCM от `ENOT_SECRET_KEY`; без ключа включение честно отказывает (`secret_key_missing`); логин без кода → честный `totp_required` до проверки пароля. Webhooks: админ настраивает URL+секрет; события `session.started`, `session.ended`, `machine.claim.denied`; подпись `X-Enot-Signature` (HMAC-SHA256), ретраи 1с/10с/60с, сбой доставки никогда не блокирует сеанс, секрет маскируется и в логи не пишется. Адаптивный битрейт видео: лестница 2500/1200/600 бит/с, вниз при потерях ≥5% или rtt>400 мс, вверх при loss<2% и rtt<150 мс не раньше 15 с после смены; цикл живёт на HOST (опрос 2 с, setParameters). First-run конфиг сервера: сохранённый в settings.json → файл `enotdesk-server.txt` рядом с exe (≤4 КБ, первая непустая строка) → вшитый при сборке (`ENOT_BAKED_SERVER_URL` через extraMetadata) → дефолт `http://127.0.0.1:8080`. Инфраструктура: docker-стек (сервер+coturn+Caddy, авто-HTTPS по `DOMAIN`), релизы GitHub Releases из тега `v*` (3 ОС + checksums + фид latest*.yml), автообновление клиента (проверка раз в сутки; Windows portable — только уведомление). Сервер: RBAC admin/operator/auditor, приглашения, адресная книга, история+аудит, per-login брутфорс-лимит, потолок живых сеансов (`ENOT_MAX_SESSIONS`), ретенция БД, бэкап VACUUM INTO, insecure-плашка без TLS. Клиент: таймер/качество/непрочитанный чат, drag&drop файлов, CSV-экспорт, один экземпляр. НЕ проверено на живых машинах (ручная приёмка — docs/MANUAL-QA.md): реальная инъекция ввода, видео/чат/файлы/терминал между машинами, службы агента на 3 ОС, реальный PTY, Win toast на живой машине, 2FA на живых аккаунтах, браузерный оператор в живом Chrome, Win/Linux-сборки; session 0 Windows (служба не видит консольный рабочий стол) и Wayland-управление — осознанные ограничения v1.

## Commands
- `npm install` — deps; node>=24.12; рантайм-зависимости только `ws`, `koffi`, `electron-updater` (точные пины) (проверено: ок, 0 vulnerabilities).
- `npm test` — node:test, 297 тестов, сервер+клиент, Electron не нужен (проверено: 297/297 pass).
- `npm run lint` — ESLint по репозиторию (проверено: чисто).
- `npm run smoke:local` — полный локальный цикл: bootstrap → login → invite/accept → session → claim → consent → WS relay → end (проверено: PASS).
- `npm run server` — сервер на `127.0.0.1:8080`, БД = `ENOT_DB` или `enotdesk.db`; `GET /api/v1/health` → `{ok,version,activeSessions,uptimeSec}` (проверено), `/downloads` (200) и `/operator` (401 анониму) на месте.
- `npm run bootstrap` — интерактивное создание первого админа (перезапись существующего отказана).
- `npm start` — Electron-клиент; смоук-прогон: `EDESK_SMOKE=1 npx electron@44.3.0 client/main.mjs --no-sandbox` (проверено: SMOKE OK, скриншот в docs/); второй экземпляр для двух ролей — `EDESK_ALLOW_MULTI=1`; изолированный профиль первого запуска — `EDESK_SMOKE=1 EDESK_SMOKE_FIRSTRUN=1`.
- `node server/backup.mjs <dbPath> <backupDir> [keep]` — бэкап `VACUUM INTO` с ретенцией свежих дампов (проверено на черновой БД).
- `sudo bash scripts/install-server.sh --backup` — консистентный дамп БД установленного сервера в backups (нужен root+сервер, здесь не прогонялся; флаги установки: --update/--no-turn/--no-tls/--reset-turn/--open-firewall/--dry-run/--uninstall/--purge-data).
- `npm run pack:mac` / `pack:win` / `pack:linux` — electron-builder из `build/electron-builder.yml`, артефакты `dist/EnotDesk-*` (macOS arm64 прогонялась ранее; Win portable exe / Linux AppImage не прогонялись).

- `ENOT_BASE_URL=… ENOT_ADMIN_LOGIN=… ENOT_ADMIN_PASSWORD=… node scripts/smoke-remote.mjs` — внешний цикл против развёрнутого сервера.

## Architecture
Attended: клиент `POST /api/v1/sessions` (без auth, rate-limit, ≤3 waiting на IP) → sessionId (9 цифр) + password + hostToken; lease 20с, host продлевает WS-heartbeat'ом каждые 5с; оператор `claim` (Bearer admin|operator) → host получает `claim` → `decision allow` → оба получают `approved`; оба подключают WS `/signal` (один сокет на участника, дубликат отклоняется), сервер релеит только offer/answer/ICE (host — оферер). Unattended: админ создаёт машину (`POST /machines` → одноразовый onboarding-код, TTL 24ч), агент обменивает код на токен (`POST /agent/register`, атомарное погашение) и живёт heartbeat'ом (`POST /agent/heartbeat`); оператор `POST /machines/:id/claim` с причиной (обязательна, ≤500) и PIN (если задан) — политику проверяет сервер, согласие человека не нужно, агент авто-allow; отказ → audit `machine.claim.deny` + webhook `machine.claim.denied`, неверный PIN бьёт лимит попыток на машину; успех → сеанс `pending-consent`, host-токен сеанса = токен машины; `GET /agent/session` отдаёт агенту его сеанс; busy/revoked — честные 409. Видео — WebRTC (TURN из `/rtc-config` ← `ENOT_TURN_*`; для терминала агента тот же endpoint с машинным токеном), ввод и сервисы — DataChannel-каналы `input`/`chat`/`clip`/`file` (ADR 0014) + `term` (ADR 0021), релей сервера не расширяется. Терминал агента: в main-процессе Electron нет RTCPeerConnection — pc живёт в скрытом BrowserWindow (`client/agent-bridge/`), `createBridgeRelay` превращает IPC-обмен в pc-подобный объект + DC-адаптер; конфиг TURN прилетает мосту до offer (`ICE_CONFIG`), краш страницы → `relay.destroy` → терминал честно закрывается; backpressure — мост следит за bufferedAmount, PAUSE/RESUME, очередь хвостом ≤1 МБ. Протокол канала `term`: host→оператор `{opened,context}|{out}|{exit,reason}|{error,code}`, оператор→host `{in}|{resize}|{close}`; открытие только внутри утверждённого сеанса (pc живёт после approved). Toast: `POST /machines/:id/toast` (admin+operator) кладёт один ожидающий запрос на машину, выдаётся агенту один раз в ответе heartbeat, результат `toastResult` (по актуальному id) резолвит ждущего оператора (≤12 с), TTL 60 с; результат ждут только по своему id. Инвентарь: heartbeat `{inventory}` → `sanitizeInventory` → колонка `machines.inventory`; `GET /machines/:id` (admin+operator) отдаёт наружный объект с инвентарём и online-статусом (окно 60 с). TOTP-логин: `POST /auth/login` без кода при включённой 2FA → 401 `totp_required` (до проверки пароля); код или резервный код (одноразовый, удаляется); `POST /auth/totp/enable|disable` — по паролю, секрет в БД только шифротекстом AES-256-GCM от `ENOT_SECRET_KEY`; disable завершает живые сеансы оператора; web-оператор пока логинится только логин+пароль (totp не шлёт) — включённая 2FA закрывает ему вход. Webhooks: `GET/POST /settings/webhooks` (только admin), `url=''` выключает, events — подмножество allowlist; `emit` асинхронный, вызывающий сеансовый код не ждёт; в журнал — только имя события и счёт попыток. Обрыв WS в approved даёт грейс `graceMs` (ENOT_GRACE_MS, 30с; 0=fail-closed) на переподключение теми же токенами с replay `approved`; до согласия — мгновенный fail-closed (ADR 0013). Решение о вводе принимает main хоста по реальному WS-состоянию (`gate.isOpen()`) → input-pipeline → koffi; заявлениям рендерера и браузера не доверять. Браузерный оператор `/operator`: страница без данных, роль по cookie `enot_op`, каждый /api и WS всё равно за RBAC; auditor — 403; CSP `script-src 'self'`; статика только по allowlist; ввод через `web/input-source.mjs`, панель машин (claim/toast/терминал/pin/revoke/delete) — только admin-функции и операции поддержки по правам маршрутов. RBAC admin/operator/auditor проверяется на каждом запросе; last active admin защищён; /audit — admin+auditor; audit+history — append-only таблицы (актор хоста — actorId=id машины, unattended=true). Ретенция (раз в час): истёкшие токены >7д, приглашения истёкшие >30д, завершённые сеансы старше `ENOT_RETENTION_DAYS` (90; 0=вечно); рестарт сервера инвалидирует живые регистрации; бэкап — `VACUUM INTO` без остановки.

## Conventions
Server pure ESM `.mjs`, node:sqlite (experimental warning — норма), без фреймворков: рантайм только `ws`+`koffi`+`electron-updater`; electron 44.3.0, koffi 3.2.1, electron-updater 6.8.9, ws 8.21.3 — точные пины, не бампать; зависимости не добавлять без явного решения. Electron: `contextIsolation: true`, `sandbox: true`, `nodeIntegration: false`; рендерер только через мост `window.enot`. Всё входящее — allowlist и лимиты (INPUT_KEYS, SDP-размеры, OPERATOR_ASSETS, инвентарь/toast, имена сборок `EnotDesk*.exe|zip|AppImage`); недоступная платформа честно сообщает статус (`native-unavailable`, `notify-unavailable`, `no-active-session`, `term-unavailable`, `wayland-unsupported-control`), никогда не фейкует успех. Токены/пароли/коды в БД только хешами; шифруемые секреты (TOTP) — AES-256-GCM от `ENOT_SECRET_KEY`; токены не утекают в renderer. Пользовательские тексты — через словари i18n (ключи ru=en, паритет проверяет контракт-тест; `error.code` не локализуется). ADR-нумерация в `docs/adr/` продолжается с 0019 (последний занятый — 0022). ## Pitfalls
koffi 3.x: `lib.func(...)` с полными C-сигнатурами; адаптеры (ввод и toast) грузятся лениво, любая ошибка → inert/честный отказ, никогда не throw; `asarUnpack: node_modules/koffi/**` в electron-builder.yml обязателен, а реинклюд-глобы JS-рантайма koffi идут ПОСЛЕ исключений `src/**` — порядок паттернов значим (последний совпавший побеждает), бинарник @koromix остаётся. i18n: ключи ru=en обязаны совпадать (контракт-тест); CSP в `client/renderer/index.html` обязан содержать `connect-src 'self' file:` — без него JSON-импорты словарей падают и ВЕСЬ граф модулей рендерера мёртв (ассерт в контракт-тесте); серверные страницы импортируют `../client/lib/i18n.mjs` — деплой-тарбалл (deploy-server.sh: server+assets+`client/lib/i18n.mjs`+`client/locales`) и Dockerfile явно копируют i18n-модуль и локали, не потерять при переносе. Single instance: второй экземпляр молча уходит, `EDESK_ALLOW_MULTI=1` — тестовый обход; агент живёт в отдельном userData-профиле со своим замком и работает рядом с обычным клиентом. compose без `TURN_SECRET` падает на интерполяции (`${TURN_SECRET:?}`); `TURN_USERNAME` ≤ 2147483647 (coturn читает как 32-бит). `BRIDGE_IPC` захардкожен в relay-контракте: sandbox-preload не может импортировать модули; electron-builder макрос `${env.*}` в extraMetadata не раскрывается — baked-адрес задаётся через `-c.extraMetadata.ENOT_BAKED_SERVER_URL`. Windows portable .exe не умеет самообновление — только уведомление; Win-служба в session 0 не видит консольный рабочий стол (осознанное ограничение v1). `npm run icons` — только macOS; `make-mascot.mjs` требует эталоны `.autopilot/enotdesk-redesign/reference/{app,site}.png` и Electron. Input decision — только в main по `gate.isOpen()`, не верить рендереру. `archive/mockup/` — макет, не приложение. NodeSource/apt на серверах ненадёжен — Node ставится tarball-ом nodejs.org с SHA256 (install-server.sh).
