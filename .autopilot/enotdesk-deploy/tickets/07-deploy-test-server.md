# 07 — Развёртывание и обкатка на тестовом сервере

**Требования:** R22, R23i, R20 (фактическая проверка), R24i
**Blocked by:** 05
**Зона:** сервер 89.125.214.92 (никаких файлов в репозитории)
**Волна:** 2
**Исполнитель:** оркестратор — пароль доступа не передаётся субагентам (правило секретов)

## Что должно заработать

На тестовом сервере (Ubuntu 24.04, root, ключ уже настроен) фактически установлен EnotDesk-сервер. Все проверки ниже выполнены и записаны с фактическим выводом.

## Критерии приёмки

- [ ] `scripts/deploy-server.sh` выполнен с локальной машины с `ENOT_DEPLOY_HOST=89.125.214.92`; установка успешна
- [ ] `systemctl is-active enotdesk` = active, `is-enabled` = enabled
- [ ] `curl 127.0.0.1:8080/api/v1/health` на сервере → `{ok:true}`
- [ ] `curl http://89.125.214.92:8080/api/v1/health` с локальной машины → `{ok:true}`
- [ ] `/downloads` и `/invite` отдают реальные страницы (HTTP 200)
- [ ] `npm test` в релизном каталоге на сервере — зелёный
- [ ] `scripts/smoke-remote.mjs` с `ENOT_BASE_URL=http://89.125.214.92:8080` — полный цикл PASS (bootstrap админа выполняется в приёмке; пароль генерируется локально и попадает только в локальный `.env`, не в отчёты/коммиты)
- [ ] Повторный `install-server.sh` (идемпотентность) — успешен, health зелёный
- [ ] `--update` с новым tarball — успешен, health зелёный, БД та же (админ сохраняется)
- [ ] `--uninstall` — сервис остановлен и удалён из автозапуска; health недоступен; БД на месте; затем повторная установка — снова зелёная
- [ ] `reboot` сервера → после возврата SSH: `is-active`=active, `is-enabled`=enabled, health зелёный (R23i)
- [ ] `--open-firewall` — если ufw неактивен, честно сообщает и ничего не меняет
- [ ] Секреты: в репозитории/коммитах/отчёте нет ни одного значения; в `.env` локально пароль админа и деплой-пароль (ENOT_DEPLOY_PASSWORD уже вписан владельцем или ввод из истории — не хардкодить)
