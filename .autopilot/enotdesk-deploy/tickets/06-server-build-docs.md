# 06 — Документация сервера и сборок

**Требования:** R21, R21.1
**Blocked by:** нет
**Зона:** `docs/`, `README.md`
**Волна:** 1

## Что должно заработать

Владелец читает `docs/SERVER.md` и понимает: как поставить сервер скриптом и вручную, как запустить, обновить, откатить, сделать бэкап, посмотреть логи, включить TLS с доменом, создать первого администратора. Читает `docs/BUILD.md` и собирает клиент под macOS (проверено), Windows и Linux (не прогонялось — честно помечено). README ссылается на оба документа.

## Разделы спецификации

Истории 6–7; Границы §4; Вне рамок §5.

## Критерии приёмки

- [ ] `docs/SERVER.md`: требования (Ubuntu/Debian, root, система); быстрый старт через `scripts/deploy-server.sh` с примером `.env`; ручная установка по шагам; управление (`systemctl status/restart`, `journalctl -u enotdesk`); обновление (`--update`); удаление (`--uninstall`/`--purge-data`); bootstrap первого админа (`sudo -u enotdesk ... npm run bootstrap`, интерактивно, пароль не эхом); бэкап и восстановление БД (`/var/lib/enotdesk/enotdesk.db`); TLS через Caddy + домен (полный пример) и явное предупреждение про тестовый HTTP; диагностика (health, порт, логи); все команды — копипастом
- [ ] `docs/BUILD.md`: общие требования (Node 24, `npm ci`); macOS — `npm run pack:mac` → `dist/EnotDesk-mac-arm64.zip`, статус «проверено на arm64»; Windows — `npm run pack:win` → portable exe, статус «не прогонялось, нужна Windows-машина»; Linux — `npm run pack:linux` → AppImage + системные зависимости, статус «не прогонялось»; разрешения macOS при первом запуске; подпись/нотаризация — что это и когда нужно; заметка про CI без секретов
- [ ] `README.md`: короткий раздел «Сервер» со ссылкой на docs/SERVER.md и «Сборка» со ссылкой на docs/BUILD.md; ничего выдуманного (никаких доменов/URL, кроме примеров-плейсхолдеров)
- [ ] Проверено: все пути существуют; все npm-скрипты из BUILD.md есть в package.json; `bash -n` не требуется, но команды валидны
