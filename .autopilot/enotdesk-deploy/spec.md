# Спецификация: развёртывание EnotDesk на сервер

## 1. Задача и решение

Владелец держит тестовый сервер (Ubuntu 24.04, root, 89.125.214.92). Нужно: поставить EnotDesk-сервер на него одной автоматической командой, получить инструкцию по установке/запуску и по сборке клиента под Windows/macOS/Linux. Решение: два скрипта — серверный установщик и локальный деплойер — плюс два документа. Сервер ставится как systemd-сервис от непривилегированного пользователя, с фиксированными путями и без секретов в репозитории.

## 3. Решения по реализации

- **Установщик `scripts/install-server.sh`** — запускается на сервере от root. Идемпотентен. Шаги: preflight (root, x86_64, наличие curl/tar/xz) → Node 24 **официальным tarball с nodejs.org (+ SHA256-проверка)** только если нет подходящего; apt на сервере не требуется — D01: 2026-09-11 развёртывание доказало, что NodeSource/apt на тестовом сервере зависает, а tarball качается мгновенно → системный пользователь `enotdesk` (без login) → каталоги `/opt/enotdesk/releases/<UTC-штамп>`, `/opt/enotdesk/current` (symlink, атомарная замена), `/var/lib/enotdesk` (БД), `/etc/enotdesk` (env) → распаковка переданного tarball с приложением → `npm ci --omit=dev` в релизе → env-файл 0600 с ENOT_HOST/ENOT_PORT/ENOT_DB/ENOT_PUBLIC_URL (+TURN при задании) → unit `enotdesk.service` (User=enotdesk, Restart=on-failure, WorkingDirectory=current, EnvironmentFile) → `systemctl enable --now` → health-poll ≤30 c → итоговая сводка. Установка Node: `NODE_VERSION` (по умолчанию пин 24.x), установка в `/opt/node-24`, симлинки в `/usr/local/bin`.
- **Устойчивость деплоя:** удалённая установка на сервере запускается через `nohup` с логом `/tmp/enotdesk-install/install.log`; локальный `deploy-server.sh` опрашивает лог и health — обрыв SSH не убивает установку (проверено фактически: предыдущий синхронный запуск был прерван таймаутом SSH).
- **Режимы:** `--dry-run` только печатает план; `--update <tarball>` ставит новый релиз и переключает symlink; `--uninstall` (БД сохраняется); `--purge-data` вместе с --uninstall.
- **Порт/фаервол:** `ENOT_PORT` (по умолчанию 8080), `ENOT_BIND` (по умолчанию 0.0.0.0). UFW открывается только флагом `--open-firewall`; если ufw неактивен — ничего не делает и говорит об этом.
- **TLS:** без домена — явный тестовый HTTP-режим (документированный риск); в docs/SERVER.md — раздел с Caddy и доменом для боевого запуска. Сервер уже умеет WS за прокси (Origin не обязателен, проверяется при наличии).
- **Деплойер `scripts/deploy-server.sh`** — локально: собирает tar.gz из `server/`, `package.json`, `package-lock.json` **и самого `scripts/install-server.sh`** → scp-доставляет tarball и установщик в `/tmp/enotdesk-install/` на сервере → ssh выполняет `bash /tmp/enotdesk-install/install-server.sh /tmp/enotdesk-install/app.tar.gz` → проверяет health на сервере и снаружи → печатает URL и следующие шаги (bootstrap администратора пользователь делает сам). Так работает и первичная установка, и обновление (`--update`). Транспорт: `scp`/`ssh`; `ENOT_DEPLOY_PASSWORD` через `sshpass` только если задан, иначе ssh-ключ.
- **Переменные** (имена, не значения, в `.env.example`): `ENOT_DEPLOY_HOST`, `ENOT_DEPLOY_USER` (по умолчанию root), `ENOT_DEPLOY_PASSWORD` (опционально), `ENOT_PORT`, `ENOT_DEPLOY_PROTO` (http/https).
- **Скрипты не печатают секреты** и не содержат их значений; `deploy-server.sh` не логирует пароль и не кладёт его в командную строку процессов сервера.
- **БД переживает релиз**: путь фиксируется в env, лежит вне релизного каталога.

## 4. Границы и швы

| Модуль | Владеет | Выставляет | Прячет |
|---|---|---|---|
| `scripts/install-server.sh` | установка и systemd на сервере | CLI: `--dry-run/--update/--uninstall/--purge-data/--open-firewall`, env `ENOT_*` | детали распаковки, health-poll |
| `scripts/deploy-server.sh` | доставку артефакта с локальной машины | CLI без аргументов, env `ENOT_DEPLOY_*` | ssh-транспорт, пароль |
| `docs/SERVER.md` | инструкцию сервера | разделы: быстрый старт, ручная установка, обновление, бэкап, логи, TLS, диагностика | — |
| `docs/BUILD.md` | инструкцию сборок клиента | разделы по ОС | — |

Швы для тестов: `bash -n` обоих скриптов; `--dry-run` на сервере; фактический install/health/reboot — приёмка R22/R23i. Юнит-тестов кода нет — это операционные скрипты.
