# Спецификация: EnotDesk — OSS-публикация, браузерный оператор, unattended-агент

## Задача

Я делаю свой инструмент удалённой поддержки EnotDesk (Node-сервер + Electron-клиент,
135 тестов, security-модель уже выстроена) и решил опубликовать его как open source,
чтобы люди хостили его сами и им пользовались. Но сейчас проект не готов к этому:
весь интерфейс только по-русски, self-host требует ручной установки Node по доке,
TURN и TLS разворачиваются руками, оператор обязан ставить desktop-клиент, а
агент-службы для обслуживания машин без человека вообще нет. Сборки неподписаны,
и я пока не готов платить за сертификаты — значит, продукт должен честно работать
и так. И главное — продукт должен быть удобным и красивым, без багов и дыр: им
будут пользоваться люди, которых я не знаю.

## Решение

Когда всё готово: человек с VPS поднимает сервер одной командой Docker — получает
HTTPS и TURN сразу, без чтения доков про Node. Интерфейс — на русском или английском
(по системе, переключается). Оператор работает либо в desktop-приложении, либо просто
открывает страницу `/operator` в браузере. Для «своих» машин — агент-служба: машина
регистрируется одноразовым кодом, дальше оператор подключается к ней без человека,
с причиной и PIN по политике группы, и всё это пишется в аудит. Релизы выходят на
GitHub Releases с checksums, клиент сам сообщает об обновлении. Неподписанные сборки
запускаются по коротким инструкциям. Проект под лицензией AGPL-3.0.

## Решения по реализации

- **Стек не меняется** (R01): Node 24 ESM, `ws`+`koffi`, Electron 44, node:test, ESLint. Почему: 135 тестов и ввод на macOS уже работают; смена стека выбрасывает наработкики.
- **i18n без библиотек**: `client/lib/i18n.mjs` (`t(key, vars)`) + `locales/{ru,en}.json`; на сервере — тот же словарь для страниц. Почему: 40 строк против зависимости; словари проверяются контрактом (ключи существуют в обоих языках).
- **Браузерный оператор — статическая страница, которую отдаёт существующий сервер** (`/operator`), переиспользует модули рендерера и `client/lib/*`. Новый код — только источник DOM-событий (`web/input-source.mjs`) и логин-форма. Никакого бандлера: ES-модули как в desktop. Почему: CSP уже есть, протоколы уже allowlist-нуты.
- **Machines — отдельный модуль сервера** `server/machines.mjs` поверх `openDb`: своя таблица `machines` (id, name, group, pin_hash, agent_token_hash, last_seen_at, tags, created_at), таблица `machine_groups` не выделяется — группа строкой на машине в v1. Миграция — через `schema_version` (A01).
- **Политики v1 = (причина обязательна) + (PIN на группе, вкл/выкл)**. PIN задаёт админ, хранится хешем; проверка на сервере при claim (не на агенте) — агент получает «claim c PIN уже проверен». Почему: один источник истины, агент не может быть обманут.
- **Агент — тот же клиент в headless-режиме** (`EDESK_AGENT=1`): переиспользует нативный ввод, захват, грейс; новый модуль `client/lib/agent.mjs` — цикл регистрации/reconnect. Почему: второй бинарник удвоил бы сборку.
- **Службы**: Windows — `sc.exe create` через install-скрипт; Linux — systemd unit с тем же хардненингом, что у сервера; macOS — LaunchDaemon. Файлы конфигурации в `client/agent-service/`, установка — по доке (`docs/AGENT.md`), инсталлятор ОС не пишем в v1.
- **electron-updater + GitHub Releases**: generic-провайдер по URL релизов; в dev отключён. Почему: без своего update-сервера.
- **Compose**: `caddy` (прокси на enotdesk:8080 + авто-HTTPS), `coturn` (static-auth-secret из env), `enotdesk` (ENOT_* env, volumes `data/` и `dist/`). Без домена Caddy слушает :8080/http и логирует предупреждение.
- **Лицензия AGPL-3.0**: заменяет автостартовавшую GPL-3.0 в пустом репо до первого внешнего контрибьютора.
- **Conventions из AGENTS.md соблюдаются**: ESM `.mjs`, без фреймворков, точные пины, русские тексты ошибок, honest status, allowlist-протоколы, контракты interfaces.md.
- **Готовые инструменты вместо самописных** (обоснование выбора, «из коробки лучше»): TURN — **coturn** (стандарт де-факто, писать свой неразумно), TLS — **Caddy** (авто-Let's Encrypt), обновления — **electron-updater + GitHub Releases** (без своего update-сервера). Альтернатива «взять RustDesk Server целиком» отклонена пользователем: цель — свой код (R01); сравнение проведено, решение зафиксировано в brief «Дополнения».

## Ресурсы и количества (что нужно и что покупать)

**Компоненты прогона (количества):** сервер+агент+desktop-клиент+браузерный оператор = 4 компонента; новых REST-эндпоинтов ~6 (machines); новых WS-типов ~3; DC-каналов 5-й не добавляется; языков 2; платформ релиза 3; целевое число тестов ≥180 (сейчас 135).

**Инфраструктура для self-host/демо (рекомендация покупателю):**
- VPS 1 шт: 2 vCPU / 2–4 ГБ RAM / 20 ГБ SSD, трафик ≥2 ТБ/мес (~$6–15/мес); 1 сеанс через TURN ≈ 1 ГБ/час.
- Домен 1 шт (~$10/год) + Let's Encrypt (бесплатно); порты 80/443, 3478 tcp+udp, 49160–49200/udp.
- Бесплатно и уже выбрано: coturn, Caddy, GitHub Actions/Releases, electron-updater.
- Отложено до бюджета: Apple Developer $99/год (notarization), Windows EV code-signing ~$200–500/год — до тех пор действует R07 (инструкции обхода).
