# Спецификация: EnotDesk — визуал по эталонам, порядок, вес и старт

## 1. Задача и решение

Владелец дал эталоны: `reference/site.png` (сайт) и `reference/app.png` (приложение). Нужно привести оба интерфейса к этому стилю, сделать сборку легче и старт быстрее, использовать маскота с эталонов как иконку приложения и разложить проект по папкам. Функционал не меняется.

Ключевые атрибуты эталона (одинаковые на сайте и в приложении): почти чёрный фон с teal-свечением, шапка «логотип + EnotDesk | Удалённая поддержка» и кнопки справа; hero с eyebrow «УДАЛЁННАЯ ПОДДЕРЖКА», огромным H1 «EnotDesk», подзаголовком и крупным teal-CTA; 3 чипа преимуществ (щит/молния/замок); маскот-енот в очках и с ноутбуком в круге свечения + рукописное «Всегда на связи ♥»; информационные карточки (платформы на сайте; Безопасно/Быстро/Удобно в приложении); 4 шага «Как это работает» на сайте; футер с версией и «С заботой о ваших задачах ♥».

## 3. Решения по реализации

**Палитра (уточняется в BRAND.md по эталонам):** фон `#070D17`, панели `#0F1A2C`, границы `#1C2C44`, акцент `#35E0C4`, текст `#EAF2FF`, вторичный `#8FA3BF`, свечение — большие мягкие радиальные тени акцента. Типографика — системный стек; H1 сайта ~64–72px, приложения ~56–64px; секции с воздухом.

**Асcеты маскота (R05).** Скрипт `scripts/make-mascot.mjs` (Electron `nativeImage`, без новых зависимостей) вырезает из эталонов:
- `assets/mascot-app.png` — маскот с ноутбуком из `reference/app.png` (hero приложения),
- `assets/mascot-site.png` — маскот из `reference/site.png` (hero сайта),
- `assets/icon-source.png` — квадратный кроп головы/плеч маскота (для иконки).
Координаты кропа подбираются фактически: после кропа PNG открывается и оценивается глазами, при необходимости координаты правятся. Штатные `sips`/`iconutil` (macOS) собирают `assets/icon.png` (1024, из icon-source с тёмным фоном), `assets/icon.icns`, `assets/icon.ico` — обновлённый `scripts/make-icons.mjs`. `assets/enot-icon.svg` остаётся для шапки/фавикона. Эталонные PNG хранятся в `.autopilot/enotdesk-redesign/reference/`.

**Визуал приложения (R01, R04, R06, R08i, R10i).** Переработка `client/renderer/index.html` + `styles.css` под эталон: шапка (логотип-иконка, «EnotDesk | Удалённая поддержка», табы-кнопки с иконками «Помощь» и «Оператор», шестерёнка настроек), hero (eyebrow, H1, подзаголовок, пояснение, большая CTA с иконкой отправки и стрелкой, строка с замком), маскот-растр в круге свечения + подпись «Всегда на связи ♥», плитки Безопасно/Быстро/Удобно, футер «EnotDesk v…» + «С заботой о ваших задачах ♥». Все существующие id/классы и вся логика (клиентские состояния, операторские панели, настройки, ввод данных, consent) сохраняются; допускается добавление обёрток и нового футера. Таб «Оператор» сохраняется (в эталоне его нет) — ради R04 «функционал сохраняем»; стилизуется как кнопка-иконка рядом с шестерёнкой. `window.enot.getSettings()` получает поле `version` (`app.getVersion()`) — иначе версия не выводится (ничего не выдумывать).

**Визуал сайта (R02, R08i, R09i, R10i).** Страницы `/downloads` и `/invite` в `server/app.mjs` переверстываются под эталон: шапка с якорями («Помощь» → секция загрузки, «Оператор» → `/invite`), hero с CTA «Скачать» и «Как это работает», чипы, секция платформ с SVG-иконками ОС и честными статусами, 4 шага с номерами и иконками, футер `EnotDesk v<cfg.version>` + «С заботой о ваших задачах ♥». Карточка платформы: иконка ОС, название, имя файла, размер в МБ и архитектура, кнопка «Скачать» с иконкой; карточка «активна», если в `ENOT_DIST_DIR` есть подходящий артефакт (так же, как сейчас определяет `distFiles`), иначе — неактивная плашка «Скоро будет» без ссылки. Рядом с маскотом — бабл «Решаем задачи на любом расстоянии ♥» из эталона. Маскот — `<img src="/brand/mascot-site.png">`; `/brand/` allowlist расширяется маскотами. Страница остаётся самодостаточной (без CDN/шрифтов/JS), адаптивной от 360px, семантичной, с focus-ring. Отдача файлов: поток с `Content-Length` и поддержкой `Range` (206 при `Range`, 200 иначе) — быстрая и возобновляемая загрузка.

**Структура проекта (R07).** Целевой вид:
```
archive/mockup/   старый корневой макет (index.html, styles.css, app.js) + README
assets/           бренд: svg, png-маскоты, icon.{png,icns,ico}
build/            electron-builder.yml (конфигурация сборки) + README
client/           приложение: main.mjs, preload.cjs, lib/, renderer/, test/
server/           контроль-плейн (пути не меняются)
scripts/          deploy-server.sh, install-server.sh, smoke-local.mjs, smoke-remote.mjs, make-icons.mjs, make-mascot.mjs
docs/             SERVER.md, BUILD.md, adr/, screenshot-main.png
BRAND.md          палитра/типографика по эталону (обновляется)
package.json      скрипты; devDependencies/electron; поле build удаляется в пользу build/electron-builder.yml
```
Переименование `desktop/` → `client/` требует обновить: package.json (скрипты `start`, `test`), `build/electron-builder.yml` (`files`, пути иконок), docs, README, AGENTS.md. `dist/` остаётся корневым выходом сборки (стандарт electron-builder и дефолт серверного `ENOT_DIST_DIR`); конфигурация — в `build/`. Публичные контракты API/WS не меняются.

**Вес и старт (R03).** `build/electron-builder.yml`: `compression: maximum`, `electronLanguages: [ru, en]`, `files: [client/**, assets/icon.*, assets/enot-*.svg, assets/mascot-*.png, package.json]`, `asarUnpack` только koffi. Замер до/после: размер `dist/EnotDesk-mac-arm64.zip` и время от старта процесса до создания окна (лог в `EDESK_SMOKE`). Ленивая инициализация koffi: загружать при первом реальном использовании (approved-сеанс), а `permissions()` отдаёт статус без принудительной загрузки; если выигрыш < 100 мс — вернуть как было и не усложнять. Цифры — фактические, в отчёт.

## 4. Границы и швы

| Модуль | Владеет | Выставляет | Прячет |
|---|---|---|---|
| `client/renderer/` | UI приложения | существующие id/классы, bridge-вызовы | вёрстку и анимации |
| `server/app.mjs` (страницы) | HTML `/`, `/downloads`, `/invite` | маршруты и `/brand/:name` | шаблоны и CSS |
| `assets/` | бренд-файлы | имена файлов из контракта | пайплайн нарезки |
| `build/electron-builder.yml` | упаковку | команды pack:* | параметры сборки |
| `scripts/make-mascot.mjs`·`make-icons.mjs` | асcеты иконок | CLI-скрипты | координаты кропа |

Швы для тестов: сервер — HTTP-шов (`/downloads` содержит hero/чипы/карточки/шаги; `/brand/mascot-site.png` 200; статусы платформ); desktop — существующие node:test по lib; UI — Electron-смоук со скриншотом главного окна; сборка — `pack:mac` + фактический размер/старт.

## 5. Вне рамок

| Требование | Почему не сейчас |
|---|---|
| Точный 3D-рендер маскота | нет генерации арта; используем кроп из эталона, пайплайн замены — одна папка assets/ |
| Смена Electron на лёгкий рантайм | это новый продукт, а не оптимизация; честные цифры вместо обещаний |
| Windows/Linux сборки | нет машин (как и раньше) |
| Мобильная версия сайта как отдельное приложение | не просили |

## 6. Открытые места

Нет placeholder-фактов: версии берутся из фактических источников, координаты кропа подбираются фактически, размеры и тайминги — измерения.
