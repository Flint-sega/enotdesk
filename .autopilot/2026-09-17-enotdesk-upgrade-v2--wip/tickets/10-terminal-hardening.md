## Что должно заработать

Терминал работает не только по LAN: мост получает iceServers из /rtc-config
(с machine-токеном) перед первым OFFER. Тесты капа очереди и гонки
ANSWER-раньше-createAnswer честные (могут быть красными). Имена BRIDGE_IPC
имеют канон и сверяются.

## Условия (заданы координатором по находкам craft)

1. iceServers из /rtc-config (machine token) → в RTCPeerConnection моста до первого OFFER; сбой/пусто → iceServers:[] + честная причина оператору.
2. Тест капа очереди: точный хвост ≤1МБ, красный при сломанном капе.
3. Тест гонки ANSWER-раньше-createAnswer (pendingAnswerSdp).
4. Канон имён BRIDGE_IPC + контракт паритета каналов (sandbox-preload не импортирует модули — тест по исходнику).

## Критерии приёмки (итог ревью)

- [x] ICE_CONFIG < OFFER, один раз за релей; сбой → честный {iceServers:[], reason}; offer не теряется
- [x] Кап-тест: 12×100024 Б + 1.5МБ → ровно хвост k003..k012 ≤1МБ, BIG роняется; красный при старом поведении
- [x] Гонка покрыта: ранний ANSWER отдаётся, кэш одноразовый, красный при потере раннего
- [x] Канон сверяется в обе стороны; Extra-поверхности нет
