# ADR 0001: оригинальное приложение на Electron/WebRTC вместо форка RustDesk

Статус: принято (T04, финальная интеграция). Дата: 2026-09-11.

## Контекст

Бриф допускал два пути: форк RustDesk или оригинальное приложение. Продукт — attended-поддержка: клиент запускает программу только на время сеанса, доступ умирает вместе с процессом; командная часть (роли, общая адресная книга, приглашения, аудит) обязательна в первом выпуске. Целевые платформы: Windows, macOS, Linux, всё portable, без установки и без служб.

## Решение

Оригинальное приложение: **Electron** (окно, захват экрана, portable-упаковка для трёх ОС), **WebRTC** (DTLS/SRTP-транспорт видео и DataChannel для ввода), сигналинг через собственный сервер **Node 24 + SQLite + ws**, нативный ввод через **koffi** (SendInput / CoreGraphics / XTest) без устанавливаемых компонентов.

### Почему не форк RustDesk

- **Идентичность времени процесса.** Ключевое требование брифа: доступ существует только пока открыт процесс клиента. RustDesk архитектурно рассчитан на сервисы/автозапуск/unattended-режим; вырезать это из форка — постоянный риск регрессии в сторону «фонового доступа», чего бриф прямо запрещает. Electron-приложение с `window-all-closed → quit` даёт нужную семантику из коробки.
- **Командный сервер в первом выпуске.** Роли, приглашения, книга, аудит — контрольная плоскость, которую пришлось бы встраивать в чужую серверную часть (RustDesk server) и держать синхронной с её развитием. Свой Node+SQLite-сервер (~один процесс) проще, прозрачнее и проверяется обычными HTTP/WS-тестами.
- **Лицензии и бренд.** RustDesk — AGPLv3: форк обязывает раскрывать исходники изменённой версии, хранить уведомления, отделять чужие товарные знаки и ассеты. Для оригинального продукта с собственной графикой это лишние постоянные обязательства. (Прежний README неверно обещал «планируемый форк RustDesk» — исправлен.)

### Почему SQLite

Один бинарный файл сервера, ноль внешних зависимостей при локальном запуске (`node:sqlite`), транзакции для CAS-операций (один оператор на сессию, однократное приглашение, защита последнего админа), переживает рестарт сервера (аудит/история/книга), при этом рестарт сам инвалидирует живые сессии — ровно нужная модель данных. PostgreSQL/MySQL ничего не дают при одном процессе и усложняют «скачал и запустил».

## Последствия и риски

- WebRTC в сложных NAT требует настраиваемого TURN (`ENOT_TURN_*`); без него подключения через симметричный NAT не гарантированы.
- Electron — большой артефакт (~130 МБ zip на macOS); плата за portable без установки на трёх ОС из одной кодовой базы.
- Нативный ввод через koffi зависит от прав ОС (macOS Accessibility) и недоступен на Wayland — диагностируется честно.
- Windows/Linux-сборки конфигурационно готовы, но реально не прогонялись (нет машин) — остаются открытыми блокерами приёмки, а не закрытыми пунктами.
- Неподписанный macOS-артефакт вызывает Gatekeeper-предупреждение; подпись/notarization — решение владельца.
