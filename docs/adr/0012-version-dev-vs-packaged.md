# ADR 0012: версия в футере — app.getVersion() в упаковке и package.json в dev (D02)

## Контекст

R10i: футер показывает фактическую версию — сайт `cfg.version`, приложение `app.getVersion()` через мост; выдуманные 1.0.0 запрещены. План считал `app.getVersion()` единым источником. Фактический dev-прогон (D02) показал: вне упаковки `app.getVersion()` возвращает версию Electron (44.3.0), а не продукта, — футер показывал бы чужую версию.

## Решение

`window.enot.getSettings().version`: в упаковке — `app.getVersion()`, в dev — версия из корневого package.json (0.1.0); версия недоступна — поле не выводится, заглушек нет. Сайт берёт версию из `cfg.version` по тому же принципу «только факт».

## Почему

Всегда брать версию из package.json — отвергнуто: в упаковке источник истины `app.getVersion()` (версия собранного продукта), и она может разойтись с репозиторным package.json. В dev не показывать версию вовсе — отвергнуто: R10i проверяется и в dev, пустой футер выглядит недоделанным. Заглушка 1.0.0 — запрещена требованием прямо. Одна ветка `app.isPackaged ? … : …` — минимальная правка, покрывающая оба режима.

## Последствия

Версия в dev и в упаковке берётся из разных источников и может отличаться, пока package.json не обновлён; bump версии делается в корневом package.json. «Упрощение» до одного `app.getVersion()` возвращает в dev футер с версией Electron (44.3.0). Проверка — Electron-смоук в обоих режимах; lib-тесты без Electron эту ветку не ловят.
