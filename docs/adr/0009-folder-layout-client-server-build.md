# ADR 0009: раскладка client/server/build/docs/assets/scripts/archive; конфиг сборки в build/, dist/ в корне

## Контекст

R07 требовал разложить проект по папкам: клиент, сервер, сборка и документы отдельно. План: `desktop/` → `client/`, поле `build` из package.json → `build/electron-builder.yml`, старый корневой макет → `archive/mockup/`. Пути при этом расходятся по package.json (`start`, `test`), build-конфигу (`files`, иконки), docs, README, AGENTS.md и скриптам; выход сборки остаётся в корневом `dist/` (стандарт electron-builder и дефолт `ENOT_DIST_DIR`), сервер и публичные контракты API/WS не меняются.

## Решение

Зафиксирована раскладка: `client/` (main, preload, lib, renderer, test), `server/` (пути не меняются), `build/` (electron-builder.yml + README), `docs/` (включая adr/), `assets/` (весь бренд), `scripts/`, `archive/mockup/`. Артефакты — в корневом `dist/`, конфигурация — в `build/`. Переезд сделан первой волной, отдельным таском от редизайна, с полным прогоном `npm test` и `pack:mac`.

## Почему

Оставить `desktop/` и build-секцию в package.json — отвергнуто: R07 прямо просит разделение, а конфиг сборки внутри package.json смешан с npm-скриптами. Перенести `dist/` в `build/` — отвергнуто: electron-builder и серверный `ENOT_DIST_DIR` по умолчанию смотрят в корневой `dist/`, перенос потребовал бы синхронной правки в двух местах без выигрыша. Совместить переезд с редизайном — отвергнуто: две волны регрессий в одном коммите, диагностика дороже, поэтому сначала структура и зелёные тесты.

## Последствия

Пути к клиенту зашиты в package.json, build-конфиге, документации и скриптах — следующее переименование снова станет массовой правкой в тех же восьми местах, `desktop/` больше не существует. Сервер остаётся независимым от клиента и обновляется отдельно. Забытая при переезде ссылка обнаруживается только при запуске соответствующего скрипта или упаковке, а не при чтении дерева.
