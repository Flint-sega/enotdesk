# ADR 0004: серверный RBAC на каждом действии с защитой последнего админа

## Контекст

Роли admin/operator/auditor обязательны в первом выпуске; сервер один, переживает рестарт; аудит фиксирует действия с actor из auth. Возможны disable пользователя и живые WS-подключения в момент отзыва прав.

## Решение

Роли admin/operator/auditor; авторизация проверяется на каждом HTTP- и WS-действии по актуальной роли и active-флагу, а не только при логине. Disable/logout закрывают связанные подключения. Последнего активного admin нельзя отключить или понизить; самоизменение роли не проходит мимо проверки.

## Почему

Рассмотрена проверка прав только на входе (токен несёт роль до истечения TTL): отвергнута — до 8 часов пониженный auditor продолжал бы claim, а отключённый оператор — держать открытый сеанс; это противоречит требованию немедленного отзыва. Рассмотрены клиентские проверки в UI: отвергнуты — сервер обязан не доверять рендереру, любой прямой запрос минуя UI обошёл бы роли. Защита последнего админа в приложении, а не транзакцией БД, отвергнута: гонка двух параллельных disable допускает команду без админа.

## Последствия

Каждое действие несёт стоимость проверки роли в БД — осознанно принято в ADR 0003. Актуализация прав при живых подключениях требует серверу активно рвать WS при disable/понижении — дополнительный код рассылки по соединениям. Сценарии гонок (два disable, self-demotion, invite-accept параллельно) становятся обязательными тестами приёмки.
