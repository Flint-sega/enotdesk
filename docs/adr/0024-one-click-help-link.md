# ADR 0024: запуск помощи одной ссылкой — протокол enotdesk://join, клиент сам создаёт сеанс, hub автоклеймит

## Контекст

R04, R07: главное в интеграции — оператор одной кнопкой зовёт клиента в сеанс удалённой помощи прямо из чата. Клиент — обычный посетитель сайта: ничего не установленно, ничего не настроено. Прецедент UX — TeamViewer/AnyDesk («ссылка→помощь»), но у нас клиент EnotDesk уже умеет сам проходить полный attended-цикл (ID/пароль → согласие клиента → сеанс), а сервер релеит только offer/answer/ICE и не знает о hub.

## Решение

Hub генерирует **одноразовый join-токен**: в БД только sha256-хеш (конвенция токенов), TTL 10 минут, привязка к треду. Клиенту в чат падает карточка «Подключиться» со ссылкой `enotdesk://join?server=<enot-url>&t=<token>`.

Протокол `enotdesk://` регистрируется **только упакованным клиентом** (`electron-builder protocols` + обработка `open-url`/`argv`/`second-instance` в main); в dev/SMOKE-режиме ссылки не работают — честное ограничение. Парсинг ссылки — чистая функция `parseJoinLink` в `client/lib/join.mjs` (шим-тесты).

Дальше клиент действует сам: ставит `serverUrl` из ссылки, **сам** создаёт сеанс (`POST /sessions` — обычный публичный маршрут с rate-limit), получает `{sessionId, password, hostToken}` и репортит в hub `POST /api/hub/join/:t/report` **только `{sessionId, password}`** — hostToken никогда не покидает клиент. Репорт одноразовый. Hub автоклеймитит сеанс bearer'ом агента из hub-сессии, в тред падает system-сообщение; оператор входит паролем, как по обычному чату. Если приложения нет — та же ссылка ведёт на fallback-страницу `/join` (скачать + инструкция + кнопка протокола), живой прогон протокола на 3 ОС — MANUAL-QA (R12).

Отвергнуто: **hostToken в URL** — URL путешествует (история браузера/лаунчера, логи, буфер обмена, REFERER), а hostToken — полный контроль сеанса; подмена или утечка ссылки стала бы компрометацией, а не «новым приглашением». **Hub создаёт сеанс за клиента** — тогда креды рождаются на сервере hub и едут к клиенту по ссылке: пароль сеанса гуляет через третью сторону и оседает в её логах; при «клиент сам» пароль рождается у клиента и доходит до оператора только через канал чата, где пароль и так легален. Регистрацию протокола в dev — отвергнуто: только упакованная сборка контролирует, что ссылка открывает настоящий клиент, а не мусорный обработчик.

## Почему

Одноразовость+TTL закрывают повторное использование просочившейся ссылки: просроченный/погашенный токен честно отказывает. «Клиент сам создаёт» переиспует уже принятый поток (`/sessions` без auth, ≤3 waiting на IP, согласие клиента) вместо нового привилегированного пути «сервер за клиента» — меньше поверхности доверия. Автоклейм из hub сохраняет политику unattended/причины/аудита на сервере EnotDesk, hub лишь предъявляет bearer агента.

## Последствия

Цепочка из трёх ходов (клик → запуск приложения → автоклейм) добавляет два новых провала к обычному флоу: протокол не зарегистрирован (fallback `/join` — это v1-ответ, не v2) и токен истёк (10 мин — повторный выпуск кнопкой, дёшево). Клиент-репорт открывает hub-маршрут, принимающий креды сеанса: он одноразовый по токену, без листинга, а пароль всё равно экранен оператору через тред — но делает тред чувствительным артефактом, о чём должны помнить ретенция и аудит hub. `second-instance`/`open-url` — третий вход в main поверх single-instance замка: `EDESK_ALLOW_MULTI`-обход не должен открывать дыру, это ловится тестами клиента. Живая проверка клика по протоколу на 3 ОС — вне автотестов, докладывается честно в MANUAL-QA.
