# ADR 0005: ввод через ограниченный JSON-enum с allowlist клавиш, не произвольные сканкоды

## Контекст

DataChannel доставляет команды ввода от оператора к нативному вводу (SendInput/CoreGraphics/XTest) на машине клиента, работающего под полной учётной записью. Протокол между рендерером и main-процессом — единственная граница между удалённым оператором и ОС клиента.

## Решение

DataChannel принимает только JSON из ограниченного enum-а сообщений: нормализованные координаты, клавиши из allowlist, ограниченные размеры и частота сообщений. Ввод активен только после согласия и установки соединения; shell/exec/файловых команд в протоколе нет. Wayland диагностируется как unsupported-control.

## Почему

Рассмотрен протокол сырых сканкодов/произвольных структур: отвергнут — превращает границу в исполнитель произвольного ввода без валидации, где ошибка рендерера или скомпрометированный операторский клиент означает keystroke-инъекцию за пределы сеанса; allowlist и лимиты делают каждое сообщение проверяемым. Рассмотрен вариант с текстовым вводом «как есть» (посимвольная вставка): отвергнут как отдельный канал — расширяет поверхность без необходимости первой версии.

## Последствия

Оператор ограничен теми клавишами, что вошли в allowlist: экзотические комбинации и макросы не пройдут — расширение allowlist будет отдельным решением. Сложные раскладки/Unicode-ввод требуют явной обработки на каждой ОС и не появляются «сами». Лимиты частоты могут ощущаться при быстрых жестах; превышение — отбрасывание сообщений, не очередь.
