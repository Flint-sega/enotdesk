# 0029. Установка машины (службы агента) из клиента; Windows-служба — отложенный автостарт; автообновление установленной сборки

Дата: 2026-10-10. Статус: принято. Наследует: 0026 (SCM-служба агента), 0014/0027 (хелпер), SEC-010.

## Контекст

Стать машиной (unattended-агентом) можно было только вручную из cmd: заполнить
`windows-install.bat`, запустить exe с `EDESK_AGENT_CODE` для первой регистрации,
поставить службу. Конкуренты (AnyDesk «Install on this device», TeamViewer — Host
изнутри QuickSupport, RustDesk — кнопка Install) делают это кнопкой в самом клиенте.
Дополнительно: (1) служба ставилась `start= auto` и на холодной загрузке порой не
успевала стартовать в 45-с окно SCM (живой случай 08.10: агент ВМ102 остался Stopped,
события 7000/7009; failure-действия стартовый таймаут не покрывают — см. ADR 0026);
(2) автообновление на Windows было выключено для ВСЕХ сборок по платформе, хотя
установленная (NSIS, Program Files) обновляется electron-updater'ом как mac/linux,
а портативная — нет (запущенный самораспаковщик не заменить).

## Решение

1. **Кнопка в клиенте** (Настройки → «Машина (постоянный доступ)», только win32,
   только упакованная сборка): пользователь вводит одноразовый код машины → main
   генерирует install-скрипт (чистый генератор `client/lib/agent-install.mjs`,
   тесты `client/test/agent-install.test.mjs`) и запускает его через
   `Start-Process -Verb RunAs` — UAC-запрос показывает Windows, всё
   привилегированное человек подтверждает сам (преемственность SEC-010).
2. **Источник файлов**: портативная сборка (env `PORTABLE_EXECUTABLE_FILE`)
   скачивает официальный `EnotDesk-win-x64-setup.exe` из релиз-фида и ставит тихо
   (`/S`) — портативку службой не делаем (самораспаковка на каждый старт = медленный
   старт службы, класс 7009). Установленная (Program Files) — ставит службу из
   локальных файлов без скачивания.
3. **Скрипт**: settings.json (адрес сервера) в профиль LocalSystem без BOM + права
   по well-known SID; `sc.exe create/config` идемпотентно с `start= delayed-auto`;
   `Environment`+`AppEnvironment` (EDESK_AGENT=1, NAME, SVC=1, +код временно);
   failure actions 5/10/30 с; рестарт; ожидание `agent-token.json` в профиле
   LocalSystem (регистрация по коду прошла); затем переписывание env БЕЗ кода
   (одноразовый секрет в реестре не хранится) — cleanup обязателен и при неудаче.
   Маркер результата `ENOT_INSTALL_RESULT=OK|FAIL …` — ASCII, парсится main из
   журнала. Ручной `windows-install.bat` остаётся (переведён на delayed-auto).
4. **Отложенный автостарт** (`start= delayed-auto`) в обоих путях установки:
   уходит от пикового шторма диска при загрузке — прагматичное лечение класса
   7009 без сервисной обвязки.
5. **Автообновление по типу сборки**: `updateInstallDecision({platform, winInstalled})`;
   `winInstalled` = упакованный win32 без `PORTABLE_EXECUTABLE_FILE`. Установленная —
   как mac/linux (качает заранее, ставит при выходе после подтверждения человека);
   портативная — только уведомление (как прежде). Служба-агент updater'а не имеет
   (AGENT-режим) — обновление службы происходит при обновлении установленного
   desktop-клиента (общие файлы Program Files) + рестарт службы.

## Альтернативы

- Ставить службу прямо из портативного exe (копия себя в Program Files) — отклонено:
  узаконивает самораспаковщик как служебный бинарник (медленный старт, тот же класс
  7009), расходится с «правильной установкой».
- MSI-сборка — отложено (NSIS perMachine уже даёт стабильный путь и elevation; MSI
  остаётся в хвостах для корпоративных развёртываний).
- Регистрация без кода (доверенный токен в install-скрипте) — отклонено: код
  одноразовый и выдаётся админом, это часть модели доверия.

## Последствия

- Порог входа для unattended равен конкурентам: скачал клиент → код от админа →
  кнопка → UAC → машина в списке операторов.
- Win-установленная сборка самообновляется (паритет с mac/linux); портативная —
  по-прежнему только уведомление (осознанное ограничение формата). Ветка
  winInstalled покрыта тестами client/test/updater.test.mjs; порядок
  подтверждения SEC-010 не менялся (renderer-contract остался прежним).
- Осталось за пределами: удаление службы из клиента (ручной windows-remove.bat /
  «Установка и удаление программ»), автообновление самого service-процесса без
  desktop-клиента, MSI.
- Таймаут elevation-обёртки 900 с (main) больше суммарного бюджета скрипта
  (~180 с setup-ожидание + установка + ~20 с рестарт + 120 с регистрация);
  таймаут убивает powershell-обёртку, но не запущенный elevated-cmd —
  установка может дозвать в фоне, UI уже сообщил об ошибке (принято для v1).
