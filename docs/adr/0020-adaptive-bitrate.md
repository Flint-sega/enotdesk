# ADR 0020: адаптивный битрейт — чистая функция над rtc-stats, ступени 2500/1200/600, гистерезис 15 с, host-сторона

## Контекст

R02: на плохой сети видео рассыпается кадрами, вместо плавной деградации; после восстановления сети качество само не возвращается. rtc-stats уже собираются (`client/lib/rtc-stats.mjs`): loss% и rtt доступны host-стороне. Применять качество надо через существующий механизм `sender.setParameters` — новая сигнальная логика не нужна.

## Решение

Политика — чистая функция `client/lib/adaptive-bitrate.mjs`: `nextTarget({lossPct, rttMs}, current, lastChangeAt, now) → {target, changed}`. Ступени фиксированные: 2500 / 1200 / 600 кбит. Вниз — при потерях ≥5%; вверх — не раньше чем через 15 с после последнего изменения (гистерезис, в обе стороны). Вызов — host-сторона: host сам измеряет канал и сам режет свой исходящий поток; потери исходящего потока берутся из `remote-inbound-rtp` (remote сообщает, что видит по нашему sender), а не из локальных счётчиков приёмника.

## Почему

Чистая функция — против логики внутри обработчика stats: ступени и гистерезис — единственная нетривиальная логика рана, она обязана покрываться таблицей тестов (ступени вниз, возврат, запрет частых подъёмов), что возможно только без DOM/WebRTC. Ступени дискретные против плавного битрейта: плавная подстройка на зашумлённых метриках осциллирует, дискрет — предсказуем и виден пользователю на индикаторе. Гистерезис обязателен: без него метрика около порога даёт пинг-понг ступеней. `remote-inbound-rtp` — против вычисления потерь из `inbound-rtp`: host — отправитель, потери его потока видит только приёмник.

## Последствия

Тюнинг ступеней/порога — правка констант одного модуля и его тестов, рендерер и main не трогаются. Функция ничего не знает о WebRTC — возвращённый `target` применяет тот, кто её вызвал (host-путь); ошибки `setParameters` не маскируются. Метрика в первые секунды сеанса шумная — политика не гарантирует мгновенной реакции, только устойчивую; это осознанный выбор против ложных просадок. Живое поведение на реальных сетях — MANUAL-QA (как и весь WebRTC-путь).
