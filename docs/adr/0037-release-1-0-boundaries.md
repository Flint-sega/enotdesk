# 0037. Границы выпуска 1.0: что обещаем, как проверяем, как выпускаем без покупной подписи

Дата: 2026-10-22. Статус: принято (решения владельца 22.10). Наследует: 0001 (Electron + WebRTC), 0029 (установка машины и автообновление), 0034 (хранение журнала).

## Контекст
Продукт работает, но «готов» нигде не определено: журнал ручных проверок (`docs/MANUAL-QA.md`) вырос в хронику на полторы тысячи строк, часть обещаний README и витрины устарела, а сквозная ревизия 22.10 нашла пункты, которые никогда не проверялись на настоящем железе (ввод через службу на реальном Windows-ПК, Mac как помогаемый компьютер, сеансы через интернет с ретрансляцией TURN). Там же выяснилось, что неподписанная mac-сборка не может поставить обновление: она скачивала новую версию, закрывалась «на установку» и запускалась снова старой.

Владелец решил сначала довести продукт до готового 1.0, а лёгкий клиент помощи на Flutter делать после — отдельной веткой.

## Решение
1. **Определение готовности** — [docs/ACCEPTANCE-1.0.md](../ACCEPTANCE-1.0.md): девять условий выпуска и матрица «сценарий × ОС × роль». Каждая строка — PASS с живым доказательством не старше 14 дней на кандидате **или** честное ограничение «ОГР 1.0», одинаково названное в README, README.ru, на витрине и в интерфейсе.
2. **Состав 1.0 по системам.**
   - Windows 10/11 — всё: клиент помощи, служба с видео и вводом (экран входа и блокировки — ADR 0036 после проверки на реальном ПК и отдельного ревью безопасности), окно оператора.
   - macOS (Apple Silicon, macOS 13+) — клиент помощи, окно оператора и **служба с видео и управлением после входа пользователя** (решение владельца: служба без видео не годится). Экран входа macOS — ограничение 1.0. Intel-Mac — нет.
   - Linux X11 — всё; GNOME Wayland — показ экрана, если подтвердится, иначе ограничение; управление на Wayland — ограничение (как сейчас).
   - Хаб — в 1.0; почтовый канал — «бета» до живой проверки с настоящим ящиком.
3. **Подпись без покупки сертификатов.**
   - macOS: собственный самоподписанный сертификат проекта (ключ — только в секретах CI). Он не убирает предупреждение при первом запуске, но даёт программе постоянную «личность»: разрешения «Запись экрана» и «Универсальный доступ» не слетают после обновлений. Самообновление на mac включается флагом сборки `ENOT_MAC_SELF_UPDATE` только после живой проверки; до тех пор — уведомление о новой версии, а `latest-mac.yml` в релиз не публикуется (иначе неподписанные клиенты 0.6.x снова попадут в петлю). Подписанной сборке — новый канал с другим именем фида.
   - Windows: заявка в бесплатную программу SignPath Foundation для open-source; при отказе — без подписи. В обоих случаях — инструкции про SmartScreen и Smart App Control.
   - Выпуск 1.0 подписи не ждёт.
4. **Безопасность и честность к человеку за компьютером.** При подключении через службу человек видит сообщение в начале и в конце сеанса; текст согласия в клиенте помощи прямо называет управление, файлы и буфер; обязательная двухфакторная защита для администраторов включается переключателем.
5. **Сеть.** Сети, где открыт только 443, — ограничение 1.0 (TURN по TLS — после 1.0). Диапазон портов ретрансляции расширяется по результатам замера.
6. **Эксплуатация сервера.** Ежедневный бэкап обеих баз плюс копия вне сервера; ключ шифрования и env хранятся отдельно от бэкапов; учения восстановления; внешний монитор доступности с оповещением; Node обновляется до последнего security-патча своей ветки не позже 14 дней.
7. **Выпуск через кандидата.** 1.0.0-rc.N на рабочем сервере не меньше 7 дней, затем 1.0.0. Проверки в рабочей среде — под отдельной учётной записью `qa`, её сеансы остаются в истории.
8. **Повторяемость.** Приёмка автоматизируется прогоном на стенде (attended и unattended); тем же прогоном и описанным протоколом сеанса потом проверяется клиент помощи на Flutter.

## Последствия
- «Готово» становится проверяемым: выпуск 1.0 — это зелёная матрица, а не ощущение.
- Пользователи mac обновляют программу вручную, пока самообновление не доказано живьём; это честнее, чем кнопка, которая закрывает программу и ничего не ставит.
- Первый запуск на macOS 15+ и на Windows без подписи требует нескольких действий — инструкции с картинками обязательны.
- Mac-служба с видео — новая работа: пара LaunchDaemon (связь, терминал, файлы) + LaunchAgent в сеансе пользователя (видео и ввод), отдельный ADR.
- Отклонено: покупка сертификатов Apple Developer и Windows (решение владельца); выпуск 1.0 «по ощущениям» без матрицы; служба Mac без видео.
