# ADR 0008: Node ставится официальным tarball вместо NodeSource/apt

## Контекст

При развёртывании на тестовом сервере (Ubuntu 24.04, root) план установщика предполагал штатный путь: `apt update` + NodeSource setup-скрипт для Node 24. Фактический прогон 2026-09-11 показал, что этот путь на данном хосте неработоспособен: `apt update` зависает на `Ign` от ubuntu-зеркал, а NodeSource setup висел более 10 минут без прогресса. При этом сервер не требует apt ни для чего другого — Node ставится один раз, зависимости приложения — через `npm ci`.

## Решение

Установщик ставит Node 24 официальным tarball с nodejs.org в `/opt/node-24`, сверяя SHA256; симлинки — в `/usr/local/bin`. apt на сервере не используется; NodeSource как источник отвергнут по факту прогона. Версия пинуется (`NODE_VERSION`), установка идемпотентна: при наличии подходящего Node шаг пропускается.

## Почему

Рассмотрен NodeSource/apt (изначальный план): отвергнут — доказано зависает на тестовом сервере, делает установку недетерминированной и блокирует R20/R22. Рассмотрены бинарники из репозитория Ubuntu: отвергнуты — старые версии Node, несовместимые с требуемым 24.x. Рассмотрена сборка из исходников: отвергнута — минуты-часы компиляции против секунд загрузки tarball, лишние build-зависимости. Tarball выбран, потому что скачивается мгновенно, версия пинована, целостность проверяется SHA256 официального релиза.

## Последствия

Загрузка идёт с nodejs.org — при недоступности сайта установка падает с явной ошибкой, а не ищет обходные зеркала; версия Node обновляется вручную правкой пина. Скрипт не зависит от состояния apt/зеркал хоста, что повышает воспроизводимость, но расходится с дистрибутивным способом — последующие системные обновления Node должны идти тем же путём. SHA256 сверяется с адресом загрузки на том же домене: защита от повреждения, не от компрометации источника; по требованию безопасности хеш можно закрепить в скрипте.
