# 0038. macOS: постоянный доступ — LaunchAgent в сеансе пользователя, с видео и управлением

Дата: 2026-10-22. Статус: принято, реализовано (ветка `feature/mac-agent-video`); живая проверка — на Mac владельца. Наследует: 0017 (агент v1), 0031 (видео Linux через мост), 0037 (границы 1.0: служба Mac с видео).

## Контекст
Mac-агент ставился LaunchDaemon'ом от root. Такой процесс живёт вне графического сеанса: macOS не даёт ему ни захват экрана, ни ввод, а разрешения «Запись экрана» и «Универсальный доступ» службе от root без MDM не выдать. Поэтому видео на Mac честно отвечало `video-unsupported-platform`, а установка требовала sudo (на Mac владельца в терминалах приложения sudo к тому же падал с ошибкой PAM). Владелец решил: служба Mac без видео для 1.0 не годится.

## Решение
1. **Агент — LaunchAgent пользователя** (`~/Library/LaunchAgents/com.enotdesk.agent.plist`): `LimitLoadToSessionType=Aqua`, `ProcessType=Interactive`, `RunAtLoad`, `KeepAlive`. Установка и удаление без sudo (`install-macos.sh`, `remove-macos.sh`); профиль — `~/Library/Application Support/EnotDesk/agent`, журнал — `~/Library/Logs/enotdesk-agent.log`.
2. **Регистрация по коду из файла** (`AGENT_CODE_FILE`): код не попадает в argv и plist, после регистрации файл удаляется.
3. **Видео** — тот же путь, что Linux (ADR 0031): `getDisplayMedia` в скрытом окне-мосте с авто-выбором первичного экрана (`setDisplayMediaRequestHandler`, без пикера — согласие даёт claim зачисленной машины). Флаг `EDESK_AGENT_VIDEO=off` выключает. Нет разрешения «Запись экрана» — мост сообщает честный статус.
4. **Ввод** — нативный адаптер CoreGraphics (тот же, что у клиента помощи на Mac); границы первичного экрана даёт Electron `screen` (в сеансе пользователя он есть). Нет «Универсального доступа» — адаптер честно отказывает.
5. **Терминал** — от имени этого пользователя (не root): это и честнее, и безопаснее.

## Последствия
- Пока никто не вошёл в систему, агент не запущен и машина офлайн — экран входа macOS остаётся ограничением 1.0 (вариант на будущее: LaunchAgent с `LimitLoadToSessionType=LoginWindow`, как у других программ удалённого доступа).
- Разрешения macOS выдаются один раз. У сборки без подписи после замены программы macOS может спросить их снова; подпись собственным сертификатом проекта (ADR 0037) это устраняет — проверить живьём.
- Прежнюю службу от root скрипты не удаляют сами (нужен пароль администратора) — подсказывают команду.
- Отклонено: LaunchDaemon + отдельный помощник в сеансе пользователя с межпроцессным каналом (как Windows, ADR 0027) — для Mac это в разы сложнее при том же результате после входа пользователя; MDM-профиль для разрешений — у владельцев небольших компаний его нет.
