# ADR 0017: unattended-агент v1 — headless-режим того же клиента со службами 3 ОС, машины с группами и политикой «причина + PIN группы, проверка на сервере, PIN только хешем», аудит actor=machine; session 0 Windows честно за v1, окна доступа отложены

## Контекст

R04/R06/R18i: нужен доступ к машине без человека — агент-служба, машина регистрируется одноразовым onboarding-кодом, оператор подключается с обязательной причиной и PIN по политике группы, всё в аудите. Текущий клиент рассчитан на attended-сеанс: человек запускает приложение и даёт согласие. По R11 живые машины пока не трогаем: сначала код, тесты, ревью.

## Решение

Агент — тот же клиент в headless-режиме (`EDESK_AGENT=1`): переиспользует нативный ввод, захват и грейс-период ADR 0013; новый модуль `client/lib/agent.mjs` (`createAgent({api, signal, native, policy})`) — цикл регистрации (обмен одноразового кода на токен машины: имя, ОС, версия), heartbeat, бесконечный авто-reconnect с backoff, переживание ребута; ввод сбрасывается при разрыве. Машины — отдельный серверный модуль `server/machines.mjs` поверх openDb: таблица `machines` (id, name, group, pin_hash, agent_token_hash, last_seen_at, tags, created_at), группа строкой на машине без отдельной таблицы групп, токен машины и PIN — только хешами в БД, повторное использование кода отклонено; миграция через `schema_version` (A01). Политики v1 = (причина обязательна) + (PIN на группе, вкл/выкл): PIN задаёт админ, проверяется на сервере при claim — агент получает «claim c PIN уже проверен»; claim без причины отклонён. Аудит и история: actor=machine, unattended=true, reason. Службы: Windows — `sc.exe create` через install-скрипт, Linux — systemd unit с тем же хардненингом, что у сервера, macOS — LaunchDaemon; файлы в `client/agent-service/`, установка по `docs/AGENT.md`, инсталлятор ОС в v1 не пишется.

## Почему

Отдельный бинарник агента — отвергнуто: удвоил бы сборку и тестовую поверхность; headless того же клиента даёт ввод, захват и грейс без нового кода, различие — один цикл в `agent.mjs`. Проверка PIN на агенте — отвергнуто: агент живёт на чужой машине и может быть подменён; сервер — один источник истины, отказ происходит до релея offer/answer, агент физически не может «простить» PIN. Таблица `machine_groups` — отвергнута в v1: группа строкой покрывает «PIN вкл/выкл», реляция понадобится вместе с окнами доступа и наследованием политик — тогда и миграция. Полноценный захват активной сессии Windows из службы (session 0) — за v1: требует отдельной проработки и это лучше честная граница, чем полусделанная фича; ограничение документируется в `docs/AGENT.md` и попадает пунктом ручной приёмки в `docs/MANUAL-QA.md` с приоритетом Windows. Окна доступа (time windows) — отложены решением пользователя («окна доступа — позже»). Инсталлятор ОС — за v1: пока живых машин нет, конфиги служб + доки достаточны.

## Последствия

Служба без окна и без согласия человека меняет модель угрозы: доступ без согласия легален только при причине, PIN-политике и полной записи в аудит — тесты на «claim без причины отклонён», «неверный/отсутствующий PIN → отказ», «верный → approved» обязательны, как и понятные ошибки без утечки деталей (ru+en). Session 0: на Windows-машине без активной пользовательской сессии захват v1 может не показать рабочий стол — это пишется как ограничение и не скрывается; живая приёмка пункта — вручную по чек-листу, когда будут машины (пользователь отложил R11 осознанно), до того интеграционные тесты идут на инертных адаптерах и фейк-сигналинге. Установка службы руками по доке — ошибиться проще, чем с инсталлятором; цена v1. Группа строкой: «переименование группы» — массовое обновление строк машин; переход на таблицу групп — через schema_version, данные не ломаются. Список машин с пагинацией и online/last seen — по живому WS/heartbeat; auditor отличает unattended-сеансы по меткам в истории и аудите.
