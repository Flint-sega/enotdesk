# ADR 0021: unattended — терминал от службы (SYSTEM v1, честно), инвентарь через HTTP-heartbeat, toast WTSSendMessageW, скрытый renderer-мост RTC

## Контекст

R06–R09: unattended-набор должен стать полноценным — терминал машины, инвентарь (ОС, версия, uptime, диск), сообщение на экран, UI машин в браузерном операторе. Агент работает как служба: Windows — SYSTEM (session 0), Linux/macOS — сервисные контексты. Утверждённый сеанс — WebRTC + DataChannel; ретрансляция сервера по ADR 0014 не расширяется.

## Решение

Терминал — DC-канал `term` поверх утверждённого сеанса, та же политика, что у claim: причина и PIN уже проверены сервером. PTY-шов `client/lib/term.mjs`: `createTerm({shell, cols, rows}) → {write, onData, resize, kill}`, платформенное — в `spawnShellFor(platform)`. Контекст v1 честный: Windows — powershell от службы (SYSTEM), Linux — `sudo -u <console-user> bash`, macOS — `launchctl asuser` + zsh. Лимиты: 1 терминал на машину, кольцевой буфер вывода 512 КБ, таймаут простоя 5 мин; открытие/закрытие — в аудит (`term.open`/`term.close`) через переходы heartbeat агента. Инвентарь — расширение HTTP-heartbeat (без отдельного канала), новые маршруты `/machines/:id/inventory`, toast — `/machines/:id/toast`. WebRTC агента живёт в скрытом renderer-мосте: main процесса без `RTCPeerConnection`, вводом управляет main по `gate.isOpen()` как раньше. Toast: Windows — `WTSSendMessageW` (wtsapi32 через koffi) в активную консольную сессию — главный путь; Linux/macOS — notify-send/osascript best-effort с честным статусом.

## Почему

SYSTEM v1 — против `CreateProcessAsUser` от пользовательской сессии: хрупко (токены, десктопы, UAC), ломается между версиями Windows; лучше честно задокументировать контекст (SYSTEM), чем притворяться пользовательским. Аудит через heartbeat-переходы — против нового server-push пути: агент уже доверенно живёт heartbeat'ом, события открытия/закрытия не требуют второго канала и не могут «обогнать» факт соединения. Инвентарь через HTTP-heartbeat — против DataChannel: админ смотрит список машин без открытого сеанса, данные должны существовать вне WS-жизни. Скрытый renderer-мост — против RTCPeerConnection в main: WebRTC в main-процессе Electron отсутствует, а главное правило (решение о вводе — только main по реальному состоянию gate) сохраняется. Единственный новый тестовый шов — `createTerm` с фейк-PTY и фейковым spawn; реальные shells не тестируются автоматически.

## Последствия

Session 0 (служба Windows не видит консольный рабочий стол) и поведение живых shells (powershell/bash/zsh под SYSTEM/sudo/launchctl) — осознанные ограничения v1, приёмка только MANUAL-QA с приоритетом Windows; докладывать честно, не выдумывать. Лимит 512 КБ кольца означает: долгий вывод теряется с начала — это задокументировано в доке и UI, не «баг». Таймаут простоя 5 мин закрывает забытые сессии, но длинная пауза оператора требует переоткрытия. `WTSSendMessageW` требует активной консольной сессии: на машине без залогиненного пользователя toast честно вернет отказ, а не «успех». notify-send/osascript — best-effort: отсутствие утилиты — статус с причиной, не фейк.
