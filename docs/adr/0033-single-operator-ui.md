# 0033. Одна программа оператора: браузерная `/operator`, desktop показывает её с сервера

Дата: 2026-10-19. Статус: принято (этапы 1–2 выполнены). Наследует: 0018 (браузерный оператор), 0030/0032 (мультиоператор, машинный join).

## Контекст
У оператора было две программы с разным кодом: desktop (`client/renderer/`: подключение, контакты, история, журнал, CSV, 2FA) и браузерная `/operator` (`web/`: подключение, машины, терминал, тосты, WoL, команда, коллеги). Ни одна не умела всего; исправления делались дважды, desktop не мог подключаться к машинам.

## Решение (владелец, 19.10)
1. Единственная программа оператора — `/operator`. Desktop показывает её **с сервера** (`<сервер>/operator` в закалённом окне: sandbox, contextIsolation, навигация только по адресу сервера); desktop-only возможности («запомнить меня») — через узкий мост.
2. Старый сервер без новой страницы — честное «обновите сервер»; встроенного запасного оператора не держим.
3. Аудитор получает в `/operator` режим «только журнал»: история и журнал действий, без подключения; права по-прежнему проверяет сервер (`/contacts` — admin/operator, `/history` — все роли, `/audit` — admin/auditor).

## Этапы
1. **Паритет web (сделан 19.10):** `web/records.js` — адресная книга (поиск, CRUD с `revision`, подтверждение удаления), история, журнал, экспорт CSV (до 1000 записей), выбор контакта в форме подключения (`contactId` в claim); видимость разделов по ролям — `applyRoleUi`; сервер отдаёт `/operator` аудитору (200), `records.js` и `client/lib/csv.mjs` — в allowlist статики.
2. **Окно оператора в desktop (сделан 19.10):** вкладка «Оператор» открывает `<сервер>/operator` в отдельном `BrowserWindow` (`openOperatorWindow` в `client/main.mjs`, чистая логика — `client/lib/operator-window.mjs`): partition `enot-operator` без `persist:` (модель SEC-008), sandbox/contextIsolation/без nodeIntegration и webview, навигация и редиректы только в origin сервера, `window.open` запрещён, разрешения — `clipboard-sanitized-write` и `fullscreen`, захват экрана — отказ, загрузки — «Сохранить как». Смена адреса сервера закрывает окно. Проверка сервера — **уровень страницы, а не номер версии**: `/api/v1/health` отдаёт `operatorUi: 1`, desktop требует `≥ 1` (номер версии ненадёжен: `package.json` в деплое может отставать от тега); нет поля — «обновите сервер», нет ответа — «сервер не отвечает». Мост `client/operator-preload.cjs` (`window.enotOperator`): только «запомнить меня» — четыре канала `enot-op:credentials-*`, отправитель — главный фрейм окна оператора с origin сервера; креды привязаны к origin (`op-credentials.mjs`), выдаются один раз за загрузку страницы, только для https или loopback (внешний HTTP может подменить посредник). Deep-link `enotdesk://invite#token=…` открывает серверную `/invite` в этом окне. Прежний встроенный оператор скрыт (`#op-legacy`) до удаления на этапе 3.
3. Удаление старого desktop-оператора после приёмки (хост-часть клиента помощи не трогается).

## Последствия
+ Одна кодовая база операторского UI; новые функции оператора приходят с обновлением сервера.
+ Desktop получит машины, терминал, тосты, WoL, подключение коллег.
− Токен desktop-оператора будет жить в странице (модель SEC-008 браузерного оператора), а не в main-процессе.
− Desktop-оператору нужен доступный сервер с новой страницей.
