# Руководство администратора сервера

Сервер EnotDesk — ваш собственный: учётные записи, машины, журналы и сеансы живут на нём. Здесь —
порядок действий; все команды и подробности — в [SERVER.md](../SERVER.md).

## 1. Поставить

Нужно: Ubuntu 22.04+/Debian 12+ (x86_64), root, домен с A-записью на сервер (для HTTPS; без домена
сервер работает по HTTP и честно предупреждает, что это только для проверки).

```bash
curl -fsSL https://raw.githubusercontent.com/Flint-sega/enotdesk/main/scripts/quick-setup.sh | sudo bash
```

Мастер спросит домен, логин и пароль первого администратора, сам поставит Node.js, сервер, TURN
(coturn) и HTTPS (Caddy), проверит работу и напечатает адреса `/downloads` и `/operator`.
Вариант в Docker — `--docker`; план без изменений — `--dry-run`.

**Откройте порты** в файрволе или группе безопасности облака: `80` и `443` tcp (сайт и HTTPS), `3478`
tcp и udp (TURN), `49160–49999` udp (ретрансляция видео). Без TURN-портов соединение между людьми за
разными роутерами часто не установится.

Проверка: `https://<домен>/api/v1/health` отвечает `{"ok":true,…}`.

## 2. Настроить команду

1. Войдите на `https://<домен>/operator` первым администратором.
2. **«Аккаунт»** → включите двухфакторную защиту (2FA) и сохраните резервные коды.
3. **«Команда»** → «Создать приглашение» с ролью (оператор / аудитор / администратор) → отправьте ссылку
   человеку (действует 24 часа).
4. Там же можно включить **«Требовать двухфакторную защиту у администраторов»**. Включить может только
   администратор, у которого 2FA уже есть. Входы администраторов без 2FA сразу завершаются, их открытые
   сеансы обрываются; после нового входа им доступна только настройка 2FA.
5. Постоянные машины — [руководство по постоянному доступу](unattended.md).

## 3. Сборки для клиентов

Страница `/downloads` показывает только реально загруженные файлы. Положите сборки нужной версии с
[GitHub Releases](https://github.com/Flint-sega/enotdesk/releases) в каталог `/var/lib/enotdesk/dist`
(имена `EnotDesk*.exe`, `EnotDesk*.zip`, `EnotDesk*.AppImage`) и сверьте их с `checksums-sha256.txt`
релиза. Если нужно заставить клиентов обновиться, задайте в `/etc/enotdesk/enotdesk.env`
`ENOT_MIN_CLIENT_VERSION=x.y.z` и перезапустите сервер — старые клиенты покажут «обновите программу».

## 4. Бэкапы — обязательно

- Установщик каждый день (04:30) делает копии обеих баз в `/var/lib/enotdesk/backups`. Это тот же диск:
  **раз в сутки копируйте их на другой сервер или в хранилище** (зашифрованно).
- **Отдельно** от копий баз храните `/etc/enotdesk/enotdesk.env` (например, в менеджере паролей):
  без ключа `ENOT_SECRET_KEY` из него пользователи с 2FA не войдут на восстановленную базу.
- Раз в квартал проверяйте восстановление на чистой машине — порядок в [SERVER.md §7.2](../SERVER.md).
  Учения 22.10.2026 на стенде заняли меньше минуты.
- Перед каждым обновлением сделайте ручную копию обеих баз (команды — [SERVER.md §7.1](../SERVER.md)):
  миграции схемы базы необратимы.

## 5. Обновить и откатить

```bash
curl -fsSL https://raw.githubusercontent.com/Flint-sega/enotdesk/main/scripts/quick-setup.sh | sudo bash -s -- --update
```

Прежние версии остаются в `/opt/enotdesk/releases/`. Откат кода: переключите ссылку `current` на
прежний каталог и перезапустите сервис (`systemctl restart enotdesk`). Если новая версия успела
изменить схему базы, старый код с ней не заработает — тогда восстановите базу из копии, сделанной
перед обновлением. Порядок отката выпуска целиком — [release-rollback.md](release-rollback.md).

## 6. Наблюдать

- Работает ли: `systemctl is-active enotdesk`, `curl -fsS http://127.0.0.1:8080/api/v1/health`.
- Журнал сервера: `journalctl -u enotdesk -n 100 --no-pager` (пароли и токены туда не пишутся).
- Поставьте внешний монитор (любой сервис проверки сайтов) на `https://<домен>/api/v1/health`
  с оповещением — сам сервер о своём падении сообщить не может.
- Кто что делал — раздел «Журнал» в программе оператора; срок хранения и очистка — там же.

## 7. Если потерян доступ

- **Админ потерял телефон и резервные коды 2FA** — снимите 2FA с консоли сервера:
  `sudo -u enotdesk env ENOT_DB=/var/lib/enotdesk/enotdesk.db /opt/node-24/bin/node /opt/enotdesk/current/server/main.mjs reset-2fa <логин>`
  (запись об этом попадает в журнал безопасности). Все входы этого человека завершаются, а его открытые
  сеансы работающий сервер оборвёт в течение нескольких секунд.
- **Забыт пароль** — сброса пароля нет: администратор удаляет участника в «Команде» (логин освобождается)
  и приглашает его заново. Последнего администратора удалить или понизить нельзя — держите двух админов.

Что-то сломалось — [«Если что-то не так»](troubleshooting.md).
