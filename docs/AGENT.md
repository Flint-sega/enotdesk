# EnotDesk — агент-служба (unattended)

Агент — это **тот же клиент EnotDesk в headless-режиме** (`EDESK_AGENT=1`): без окна и рендерера,
с отдельным профилем. Он регистрируется на сервере по одноразовому onboarding-коду, обменивая его на
токен машины, затем живёт как служба: auto-reconnect с backoff, heartbeat каждые 5с, переживает ребут
и обрывы связи, принимает claim оператора (причина обязательна, PIN-политика сервера — на сервере).

Пошаговое руководство для людей — [guides/unattended.md](guides/unattended.md). Одноразовый код машины
выдаёт админ в программе оператора: «Машины» → «Добавить машину». Windows: служба ставится из самого
приложения (Настройки → «Машина (постоянный доступ)», ADR 0029); Linux и macOS — скрипты
`client/agent-service/` (windows.md, linux.md, macos.md). Живая установка — ручная приёмка по `docs/MANUAL-QA.md`.

## Где что лежит (профиль агента)

Профиль агента отделён от профиля обычного клиента: `<userData>/agent/`. Так как служба обычно
работает от служебной учётки, фактические пути:

| ОС | Профиль агента | Токен машины |
|---|---|---|
| Windows (служба от LocalSystem) | `C:\Windows\System32\config\systemprofile\AppData\Roaming\EnotDesk\agent` | `...\agent\agent-token.json` |
| Linux (user `enotdesk-agent`) | `/var/lib/enotdesk-agent/.config/enotdesk/agent` (строчные — имя пакета) | `.../agent/agent-token.json` |
| macOS (LaunchAgent в сеансе пользователя, ADR 0038) | `~/Library/Application Support/EnotDesk/agent` | `.../agent/agent-token.json` |

В профиле: `settings.json` (адрес сервера; если запускаете агент вручную в своей сессии —
`%APPDATA%\EnotDesk\agent` / `~/.config/enotdesk/agent` / `~/Library/Application Support/EnotDesk/agent`).

**Токен машины** — секрет, дающий право занимать слот машины. Файл 0600. «Забыть» машину на этой
железке: удалить `agent-token.json` (или весь `agent/`) — при следующем старте понадобится новый
onboarding-код. Отзыв на стороне сервера: список машин → отозвать/удалить (старый токен перестаёт
приниматься, даже если файл остался).

## Переменные окружения агента

| Переменная | Значение |
|---|---|
| `EDESK_AGENT=1` | включает headless-режим (обязательно) |
| `EDESK_AGENT_NAME` | имя машины в списке; по умолчанию hostname |
| `EDESK_AGENT_CODE` | одноразовый onboarding-код — **только для первой регистрации**, в конфиге службы не хранить |

## Установка по ОС

- **Windows (приоритет)**: `sc.exe create` (start= delayed-auto, description, автоперезапуск при сбоях,
  переменные через `Environment` + `AppEnvironment`). См. `client/agent-service/windows.md`, скрипты
  `windows-install.bat` / `windows-remove.bat`. Установка идемпотентна: повторный запуск
  на существующей службе обновляет конфиг и перезапускает её (апгрейд бинарников —
  просто заменить файлы и перезапустить скрипт; ранее апгрейд оставлял службу Stopped).
- **Linux**: systemd unit с хардненингом как у сервера (`NoNewPrivileges`, `ProtectSystem=strict`,
  `ReadWritePaths` на профиль, `Restart=always`). См. `client/agent-service/linux.md`,
  скрипты `install-linux.sh` / `remove-linux.sh`.
- **macOS**: LaunchAgent в графическом сеансе пользователя (`LimitLoadToSessionType=Aqua`,
  `RunAtLoad`, `KeepAlive`), установка без sudo — ADR 0038. См. `client/agent-service/macos.md`,
  скрипты `install-macos.sh` / `remove-macos.sh`.

Порядок на любой ОС один: (1) распаковать сборку; (2) первая регистрация вручную с
`EDESK_AGENT_CODE` (код одноразовый и остаётся только на сервере); (3) поставить службу — она
стартует уже с токеном; (4) проверить на сервере, что машина online.

## Обновление

Токен живёт в профиле агента и переживает замену файлов сборки:

- **Windows, установленная сборка** (служба поставлена из приложения) обновляется сама; служба
  переживает обновление (ADR 0029, installer.nsh).
- **Windows вручную, Linux:** остановить службу (`sc stop EnotDeskAgent` / `systemctl stop enotdesk-agent`),
  заменить файлы сборки, запустить обратно.
- **macOS:** заменить `/Applications/EnotDesk.app` и перезапустить агент:
  `launchctl kickstart -k gui/$(id -u)/com.enotdesk.agent`.

Версию машины видно на сервере в списке машин (агент отчитывается `version` при регистрации).
Если машина не поднялась после обновления — логи (ниже), там честная причина.

## Логи

| ОС | Где логи |
|---|---|
| Windows | `enotdesk-boot.log` в профиле агента (таблица выше) — запуск и обновления; `C:\ProgramData\EnotDesk\enotdesk-video.log` — видео и ввод хелпера; по маркеру `C:\ProgramData\EnotDesk\svc-diag.enabled` — подробный `svc-diag.log` службы. SCM-ошибки запуска — в Event Viewer (System). |
| Linux | `journalctl -u enotdesk-agent -f` |
| macOS | `~/Library/Logs/enotdesk-agent.log` (StandardOutPath/StandardErrorPath), плюс Console.app |

## Windows: что умеет служба — честно

Служба работает в session 0, а экран и ввод обслуживает видеохелпер `enotdesk-video.exe`, который
служба запускает в консольном сеансе пользователя (ADR 0027): захват DXGI (на адаптерах без него — GDI),
ввод SendInput.

- работает: регистрация, онлайн, причина и PIN, видео рабочего стола и управление (проверено на
  виртуальных машинах стенда; на реальном ПК — проверяется, ACCEPTANCE W-3/W-4), терминал от SYSTEM,
  сообщение на экран, чат (в одну сторону: текст оператора показывается сообщением), файлы (в одну
  сторону: в общую папку `%PUBLIC%\EnotDesk Files`), автоперезапуск и переживание перезагрузок;
- пока нет: экран блокировки, экран входа и окно UAC (ветка ADR 0036, сливается после проверки на
  реальном ПК); буфер обмена в сеансе машины. До 0.6.29-pre.6 клавиши и кнопки мыши через службу
  получали отказ Windows (не хватало права на рабочий стол ввода, ADR 0027 addendum 4) — обходом был
  `ENOT_VIDEO_ATTACH=off` в Environment службы; теперь он не нужен.

Аналогичные честные ограничения других ОС: Wayland на Linux — управление вводом не поддерживается
(`wayland-unsupported-control`); Linux без графического сеанса — агент в безэкранном режиме (без видео и
ввода); macOS — агент работает только в сеансе вошедшего пользователя (экран входа macOS — ограничение
1.0), видео и управление требуют один раз выданных разрешений «Запись экрана» и «Универсальный доступ».
Детали — в соответствующих `client/agent-service/*.md`.

## Ограничения Linux/macOS unattended — честно (волна 0.6.19)

- **Unattended-видео вне Windows** идёт через захват getDisplayMedia в скрытом окне-мосте:
  Linux X11 — ADR 0031, macOS — ADR 0038 (агент в сеансе пользователя). Если захват недоступен
  (нет разрешения, Wayland без портала, нет графического сеанса), оператор видит честный статус,
  а не чёрный экран.
- **Wayland-сессии**: управление честно отказывает (`wayland-unsupported-control`); видео через
  Xwayland показывало бы не все окна (нативные Wayland-окна невидимы) — потому и не заявлено.
- **Email-ретенция хаба**: дедуп-окно `email_seen` — 90 дней (часовой уборщик). Ответ на
  письмо старше 90 дней откроет НОВЫЙ тред, а не продолжит старый (исходящий ответ по
  дормантному треду уйдёт без In-Reply-To — доставка не страдает). Осознанный трейд-офф.
- **Терминал без PTY (v1)**: оболочка живёт на пайпах child_process — эха и приглашения строки
  нет, команды выполняются вслепую (ввод нормализуется: `\r` панели → `\n` для пайп-bash).
  kilл терминала снимает всё дерево оболочки (спавн в своей группе процессов, `kill(-pgid)`):
  обёртки `sudo -u`/`launchctl asuser` и потомки умирают вместе с группой. Граница: при КРАХЕ
  самого агента detached-оболочка доживёт до рестарта службы — юнит агента (KillMode=control-group
  по умолчанию systemd) прибирает cgroup при stop/restart. Смена консольной сессии Linux
  (logout/login, X11↔Wayland) требует перезапуска агента: DISPLAY/XAUTHORITY читаются при
  старте юнита (лабовый glue enot-xauth-sync).

## Ручная приёмка

Чек-лист живой проверки (attended + unattended, приоритет Windows): `docs/MANUAL-QA.md`.
Живую установку служб выполняет владелец по этому чек-листу; автотестами служебные конфиги не
проверяются (только синтаксис доступными средствами).
