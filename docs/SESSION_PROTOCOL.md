# EnotDesk session protocol

## Жизненный цикл

1. Portable-клиент стартует и явно показывает согласие на поддержку.
2. Клиент генерирует случайный session ID и одноразовый secret.
3. Credentials передаются оператору через защищённый канал чата.
4. Rendezvous-сервис проверяет срок, статус процесса и одноразовое использование.
5. При подключении создаётся audit event с оператором, клиентом и временем.
6. При закрытии приложения или нажатии «Завершить поддержку» secret немедленно отзывается.

## Нельзя

- постоянный пароль по умолчанию;
- скрытая установка или автозапуск;
- подключение без подтверждения клиента;
- хранение secret в логах;
- использование публичного relay без явной конфигурации сервера.

## Контракты будущего MVP

- `POST /v1/sessions` — создать временную сессию;
- `POST /v1/sessions/{id}/claim` — оператор предъявляет secret;
- `POST /v1/sessions/{id}/revoke` — завершить сессию;
- `GET /v1/audit` — журнал для авторизованного оператора.
