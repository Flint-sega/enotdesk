# Приёмка 1.0 — что значит «готово»

Определение готовности EnotDesk 1.0 (ADR 0037). Каждая строка ниже — PASS с живым доказательством
не старше 14 дней на сборке-кандидате 1.0.0-rc.N **или** «ОГР 1.0» — честное ограничение с одинаковым
текстом в README, README.ru, на витрине и в интерфейсе. P0-строк в ограничениях — 0, всего ограничений —
не больше 20% строк. Подробные протоколы проверок — [MANUAL-QA.md](MANUAL-QA.md).

Статусы: **PASS** — есть живое доказательство (дата); **ЧАСТ** — частично или на старой версии; **НЕТ** —
не проверялось; **СЛОМ** — доказано, что не работает; **ОГР** — ограничение 1.0. Статусы — на 25.10.2026.

## Условия выпуска 1.0
1. Каждая строка матрицы — PASS или ОГР (см. выше).
2. Автоматический прогон приёмки (attended Windows 10/11 и Linux X11, unattended Windows/Linux) зелёный 3 раза подряд.
3. Собранные программы трёх ОС стартуют в CI (смоук артефактов).
4. В каждом канале обновления — обновление N-1→N или честное уведомление со ссылкой; нет кнопки «Обновить», которая ничего не делает.
5. Сервер: ежедневный бэкап обеих баз и копия вне сервера; учения восстановления ≤30 мин; внешний монитор с оповещением ≤10 мин; Node — последний security-патч 24.x.
6. Ревью безопасности кандидата: открытых P0/P1 — 0; `npm audit --omit=dev` без high/critical (или письменное обоснование).
7. Сеть через интернет: разные домашние NAT, мобильный интернет, принудительная ретрансляция TURN, закрытый UDP.
8. Документы не обещают того, чего нет; есть руководства клиенту, оператору, админу сервера, для постоянного доступа и «если что-то не так».
9. Кандидат проработал на рабочем сервере не меньше 7 дней без инцидентов P0/P1.
