# Агент-служба Windows (sc.exe)

Служба ставится штатным `sc.exe`, без своего инсталлятора (решение v1, spec §службы).
Скрипты: `windows-install.bat` / `windows-remove.bat` — запускать в cmd **от имени администратора**.

## Что делает install-скрипт

1. Пишет `settings.json` (адрес сервера) в профиль агента. Служба работает от `LocalSystem`,
   поэтому профиль — `%SystemRoot%\System32\config\systemprofile\AppData\Roaming\EnotDesk\agent`
   (не `%APPDATA%` администратора, запускающего скрипт).
2. `sc.exe create ... start= auto obj= LocalSystem DisplayName= "EnotDesk Agent"` — автостарт при загрузке.
3. `sc.exe description ...` — описание службы.
4. Переменные процесса службы через `reg add ...\Services\EnotDeskAgent /v AppEnvironment /t REG_MULTI_SZ`:
   `EDESK_AGENT=1` (headless-режим) и `EDESK_AGENT_NAME` (имя машины в списке, по умолчанию `%COMPUTERNAME%`).
   AppEnvironment — старый механизм SCM, работает на всех поддерживаемых Windows. На Windows 10 2004+ есть
   также значение `Environment` (REG_MULTI_SZ) — можно использовать вместо AppEnvironment, но держать
   оба одновременно не нужно.
5. `sc.exe failure ...` — автоперезапуск при сбоях: через 5с, 10с, затем 30с (счётчик сбрасывается раз в сутки).
6. Запуск службы.

## Перед установкой: первый запуск и onboarding-код

Рекомендуемый порядок — код используется один раз и нигде не хранится:

```bat
:: в консоли администратора, до установки службы
set EDESK_AGENT=1
set EDESK_AGENT_NAME=PC-BUH-01
set EDESK_AGENT_CODE=123456789
"C:\Program Files\EnotDesk\EnotDesk.exe"
:: дождитесь в логе «запущен», закройте (Ctrl+C / закрытие консоли)
```

Токен сохранится в `...\EnotDesk\agent\agent-token.json` (LocalSystem-профиль — файл туда попадёт,
если переменные задать так же, как их получит служба; при запуске из своей сессии профиль другой —
см. «Диагностика» ниже). Затем запустите `windows-install.bat` — служба стартует уже с токеном,
без кода.

Альтернатива без ручного запуска: добавьте `EDESK_AGENT_CODE=<код>` третьей строкой в `AppEnvironment`
(в install-скрипте), после успешной регистрации снимите эту строку командой из раздела «Диагностика» —
код в реестре хранить нельзя, он одноразовый.

## Диагностика и просмотр конфигурации

```bat
sc.exe query EnotDeskAgent
sc.exe qc EnotDeskAgent
reg query "HKLM\SYSTEM\CurrentControlSet\Services\EnotDeskAgent" /v AppEnvironment
```

**Логи в v1 не пишутся на диск** — у процесса службы нет консоли, stdout теряется. Для диагностики
остановите службу и запустите агент в своей консоли:

```bat
sc.exe stop EnotDeskAgent
set EDESK_AGENT=1
set EDESK_AGENT_NAME=PC-BUH-01
"C:\Program Files\EnotDesk\EnotDesk.exe"
```

Учтите: так агент работает от вашего пользователя, и его профиль (`%APPDATA%\EnotDesk\agent`) отличается
от профиля службы (systemprofile). Чтобы увидеть «как у службы», скопируйте `settings.json`/`agent-token.json`
в свой профиль или наоборот. Честное ограничение v1: файлового логирования службы нет — пункт 8 в
`docs/MANUAL-QA.md`.

## Удаление

`windows-remove.bat`: останавливает и удаляет службу, спрашивает, удалять ли профиль агента
(токен + настройки). Запись машины на сервере удаляется отдельно (список машин → удалить/отозвать).

## Ограничение session 0 — честно (история 31)

Служба Windows исполняется в **session 0**: у неё нет доступа к интерактивному рабочему столу
пользователя (консольная сессия живёт в session 1+). Следствия для v1:

- **Работает**: регистрация, heartbeat/online, принятие claim с причиной, PIN-политика, чат,
  буфер обмена и передача файлов (DataChannel), переживание ребута и обрывов связи.
- **Не работает / ограничено**: захват экрана консольной сессии (`desktopCapturer` в session 0 не видит
  рабочий стол пользователя — пустые источники/чёрный кадр) и инъекция ввода в неё (`SendInput` из
  session 0 не доходит до сессии пользователя). Ввод и видео интерфейсов, открытых внутри session 0
  (экран входа/сервисные окна), — теоретически возможны, но это не сценарий удалённой помощи.

Unattended-поддержка активной консоли Windows требует отдельного helper-процесса в сессии пользователя
(брокер/RunAs), — это **осознанно отложено за рамки v1**. Пункт ручной приёмки, фиксирующий ожидаемое
поведение: `docs/MANUAL-QA.md`, Windows-U7.
