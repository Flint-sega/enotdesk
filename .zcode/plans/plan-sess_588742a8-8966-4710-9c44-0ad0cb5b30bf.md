# План «лучший продукт» — 4 волны

Каждая волна: код + тесты + `npm test` зелёный + `smoke:local`; коммит в конце волны. Все тексты пользователя — по-русски. Контракты из `.autopilot/enotdesk-redesign/interfaces.md` не ломаем (расширяем, ADR на изменения).

## Волна 1 — Критичные фиксы (P1)

1. **Клавиатура на любой раскладке.** Рендерер маппит по `e.code` (физическая клавиша): новая чистая функция `keyFromCode(code, key)` → вынести в `client/lib/keymap.mjs` (тестируема без Electron). `KeyA`→`a`, `Digit1`→`1`, `Space`→`space`, `Backquote`→`` ` `` и т.д.; раскладка перестаёт влиять. Тесты: полная карта кодов в `client/test/`.
2. **Ворота ввода не закрываются на транзиентные ошибки.** `protocol.mjs:createInputGate`: `error` больше не закрывает ворота — только `ended`/`socket-closed`/закрытие соединения. Коды ошибок сервера (`rate_limited`, `bad_signal`) показываются оператору в `remote-status` (сейчас `app.js:306` их игнорирует). Тесты на гейт + контракт.
3. **Калибровка скролла.** Рендерер нормализует дельту в строки (`Math.round(dy/40)`, клэмп ±50/событие); хост: mac — строки как есть (`CGEventCreateScrollWheelEvent`, unit=0), win — `lines*40` (3 строки = 120 = один щелчок), X11 — 1 щелчок колеса на 3 строки. Хелперы масштабирования — чистые функции, покрыть юнит-тестами. Живую проверку на 2 машинах отмечаем как ручной шаг приёмки.
4. **Клик без движения не бьёт в угол.** Рендерер перед `button.down` всегда шлёт `move` с текущими нормализованными координатами.
5. **RateLimiter не течёт.** `app.mjs`: инжектимый `nowFn` в конструктор; при размере Map > 5000 — выметание протухших окон; юнит-тест.
6. **Лимиты при приёме приглашения**: `name ≤ 120`, `login ≤ 32` (`app.mjs` invites.accept) + тесты.
7. **Bounds-защита**: `selectSource` без дисплеев → честная ошибка; диспетчер отказывает `no-bounds`, если width/height = 0 (только для move).
8. **Чистка**: мёртвый `client-native-note` (index.html), мёртвый цикл `AMBIGUOUS` (crypto.mjs), явный `import crypto` в app.mjs, `ws._userId` → переменная замыкания, буфер `seen` в signal.mjs с потолком 100, дубли циклов по `live` в members → хелпер.

## Волна 2 — Грейс-период переподключения (ADR 0013)

- Сервер (`app.mjs`): в состоянии `approved` обрыв WS больше не завершает сеанс мгновенно — `graceMs` (конфиг `createServer`, env `ENOT_GRACE_MS`, дефолт 30с; 0 = старое поведение). Sweeper завершает `host-lost`/`operator-lost` только по истечении грейса. До `approved` — как сейчас (fail-closed). Повторная аутентификация теми же токенами (hostToken / claimId) в течение грейса → `resumed`, обе стороны получают уведомление.
- Токены не меняются, ввод безопасен: ворота на клиенте закрыты всё время разрыва, открываются только после реального повторного `approved`.
- Клиент: состояние «Переподключение…» вместо мгновенного «Сеанс завершён»; RTC: `disconnected` → ждём 10с до разборки, `failed` → сразу.
- ADR 0013 (смена fail-closed модели, границы грейса), тесты: reconnect в грейс / вне грейса / до approval; клиентский тест ворот.

## Волна 3 — Фичи сессии (ADR 0014: каналы поверх DataChannel, релей сервера не трогаем)

Отдельные DC-каналы с allowlist имён: `input` (есть), `chat`, `clip`, `file`. Все протоколы — ограниченные, с лимитами; общие хелперы в `client/lib/` (чистые, тестируемые):
- **Чат**: JSON-сообщения ≤2000 символов, обе стороны, панель чата у клиента и оператора, только в течение сессии (не персистится).
- **Буфер обмена**: текст ≤100 КБ, обе стороны, выключатель в UI («Синхронизация буфера: вкл/выкл», по умолчанию выкл у клиента).
- **Файлы**: оператор→клиент только с явным «Принять/Отклонить» у клиента; клиент→оператор принимается оператором. Чанкинг 64 КБ + meta-JSON, потолок размера (200 МБ), backpressure через `bufferedAmountLowThreshold`, прогресс в UI. Хелперы чанкинга/сборки — юнит-тесты.
- **Видео-UX**: полноэкранный режим, переключатель «вписать/100%», ограничение качества (maxBitrate ~2.5 Мбит/с через `RTCRtpSender.setParameters`), кнопка «Сменить экран» у клиента на ходу (replaceTrack, без ренегоциации).
- Контракт-тесты рендерера обновить; renderer-contract дополняется новыми элементами.

## Волна 4 — Эксплуатация и гигиена

- **Ретенция** (sweeper расширяется): истёкшие `auth_tokens` старше 7д, использованные/отозванные `invites` старше 30д, завершённые `sessions` старше `ENOT_RETENTION_DAYS` (90); потолок «waiting»-сессий с одного IP (≥3 → 429); `/health` отдаёт `activeSessions` и uptime; тесты.
- **Страницы**: CSP + `X-Content-Type-Options` + `X-Frame-Options` в `page()`; HEAD для `/downloads-files` (stat → Content-Length).
- **RBAC аудита**: `/audit` — admin+auditor (тесты обновить); `actor_id='host'` → NULL + `detail.host=true`.
- **Разделение**: `server/pages.mjs` — BASE_STYLE/ICONS/STEPS/HTML-билдеры (app.mjs худеет на ~250 строк).
- **systemd**: `ProtectSystem=strict`, `ReadWritePaths=/var/lib/enotdesk`, `PrivateTmp=true`; SIGTERM в `server/main.mjs` → `inst.close()`.
- **CI**: `.github/workflows/test.yml` (node 24: `npm ci && npm test`) на push/PR.
- **TLS-история**: docs/SERVER.md — готовый раздел reverse-proxy (Caddy, автоматический HTTPS); опция в install-server.sh — отдельным решением, документация первична.
- ADR 0014 (фичи), обновление AGENTS.md/README (команды, тесты, честный статус «проверено вручную/нет»).
