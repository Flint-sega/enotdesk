# EnotDesk Hub — тикет-система + чат-виджет с интеграцией EnotDesk (новый Foreman-прогон)

Отдельный сервис в том же монорепо, ставится вместе с EnotDesk (compose/quick-setup спрашивает), взаимодействует по REST/SSO. Ориентир UX — livechat.com (лайт): инбокс, canned-responses по #, теги, рейтинг чата, offline-форма→тикет, pre-chat с GDPR-строкой; архитектурные паттерны — Chatwoot (единая модель Conversation+Message, embed одним <script> + iframe, IMAP-поллинг). Отброшено: боты, мультиканальность (WhatsApp/TG), отчёты, база знаний, SLA.

## Архитектура

- **`hub/`** — чистый Node ESM без фреймворков (как server/: node:http + ws), собственная SQLite `hub.db` (schema_version-миграции по нашему паттерну), порт `ENOT_HUB_PORT` (8090), за Caddy на том же домене: `/hub/` консоль, `/widget.js` + `/w` виджет, `/join` fallback-страница.
- **Новые зависимости (первое добавление со старта, решено владельцем)**: `imapflow` + `nodemailer`, точные пины.
- **SSO через EnotDesk**: логин в hub → прокси `POST /auth/login` EnotDesk; hub-сессия = HttpOnly-cookie sid → запись с bearer (TTL по токену, ревалидация /auth/me); роли operator/admin из EnotDesk. 2FA наследуется автоматически.
- **Модель (Chatwoot-стиль)**: `contacts` (visitor_id/email), `threads` (channel: chat|email|manual; status open|pending|resolved; assignee, tags, rating, last_activity) + `messages` (author: contact|agent|system; type: text|card|note). «Тикет» = thread в UI.
- **Виджет**: одна строка на сайт `<script src="https://домен/widget.js" data-server="https://домен"></script>` → iframe-пузырь → WS-канал гостя (visitor_id-cookie на домене хаба, история на сервере), pre-chat форма (имя/email опционально + строка согласия), **offline-форма → тикет (email-канал)**; CORS-allowlist доменов сайта (настройка админа, эхо Origin).
- **One-click помощь из чата** (безопасно, без hostToken в URL): агент жмёт «Подключиться» → hub генерирует **одноразовый join-token** → карточка с кнопками «Запустить помощника» (`enotdesk://join?server=…&t=…`) и «Скачать». Клиент (новое): регистрирует протокол `enotdesk:` (electron-builder protocols; win/mac/linux) + парсит ссылку → подставляет сервер, **сам создаёт сеанс (как сегодня) и репортит {sessionId,password} в hub по одноразовому URL** → консоль агента автоклеймит (bearer агента уже в hub-сессии), в тред падает system-сообщение. Fallback `/join` — страница с той же кнопкой + скачивание + инструкции. Webhooks session.started/ended → system-сообщения в связанный тред.
- **Email-канал**: IMAP-поллер (интервал, уведомления) → тред по Message-ID/In-Reply-To или from+subject; SMTP — ответы агентов уходят клиенту с почты; креды в настройках админа, пароль IMAP/SMTP шифруется AES-256-GCM от `ENOT_SECRET_KEY` (паттерн totp-хелперов).
- **i18n**: ключи `hub.*`/`widget.*` в те же `client/locales/{ru,en}.mjs` (hub импортирует их же) — паритет-тест.
- **Деплой**: compose-сервис `hub` (x-hardening, depends_on enotdesk, env ENOTDESK_URL/ENOT_SECRET_KEY/HUB_URL) + Caddy-маршруты; quick-setup вопрос «Установить EnotDesk Hub?» (bare-metal: второй systemd-юнит enotdesk-hub).

## Таски (4 волны, ревью 2 осями как обычно)

- **T01 hub-каркас**: node:http-сервер, db-миграции, SSO-прокси+cookie-сессии, health, статика консоли (тёмная тема /operator-стиль), i18n, compose+quick-setup+installer-хвосты. Тесты: SSO (фейк-EnotDesk), сессии, health.
- **T02 тикеты/консоль**: contacts/threads/messages REST + UI-инбокс (список, фильтры статус/канал/тег/assignee, поиск, пагинация), детали треда, ответ агента, canned responses (#-автодополнение), теги, статус agента (online/away/offline → виджет честно показывает offline), rating после чата; ручные тикеты от операторов. Тесты: CRUD/RBAC/контракты UI.
- **T03 виджет**: loader widget.js, iframe /w (пузырь/чат, mobile fullscreen), WS гость-канал (reconnect, typing-индикатор v1 — опционально), pre-chat/offline-формы, visitor-история, CORS-allowlist. Тесты: WS-цикл гостя, offline→тикет, CORS-эхо, контракты.
- **T04 one-click клиент**: protocols electron-builder + main.mjs (open-url/argv/second-instance, single-instance не мешает), парс join-ссылки, автостарт сеанса + репорт в hub; /join-страница. Тесты: парсер-юнит, wiring-контракты; живой прогон протокола — MANUAL-QA.
- **T05 карточка из чата**: agent action → join-token → карточка; автоклейм при репорте; webhooks→тред. Тесты: сквозной фейк-цикл (hub+EnotDesk+фейк-клиент).
- **T06 email**: imapflow-поллер + nodemailer, настройки админа (шифрование кред), inbound-маппинг, ответы→SMTP. Тесты: парсер/маппер на фикстурах, поллер на фейк-IMAP (инъекция), креды не в логах.
- **T07 приёмка**: ADR 0023-0025 (hub-архитектура+SSO, one-click протокол, email-канал), MANUAL-QA (живые: виджет на реальном сайте, протокол на 3 ОС, IMAP-ящик), README/AGENTS, слепая проверка, релиз v0.3.0 — по команде (наружное).

## Верификация

Каждый таск: код+тесты+lint+smoke; цель 335 → ~430+ тестов. Финал: слепая приёмка, live-проверки честно в MANUAL-QA (живой тест отложен решением владельца — код и фейки только).
