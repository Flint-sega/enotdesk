# Однокомандная установка сервера — quick-setup.sh (bare-metal + docker)

Цель: на чистой VPS пользователь выполняет ОДНУ команду, отвечает на 4-5 вопросов (домен, логин, пароль, порт, firewall) — и получает работающий сервер с созданным админом, TURN/TLS и секретами. Никакого ручного ssh-bootstrap, никаких экспортов переменных.

## T1. release.yml: серверный тарболл + env-хвосты установщика

**release.yml**: новый job `server-tarball` (ubuntu, без Node) — `tar -czf enotdesk-server.tar.gz` составом ровно как deploy-server.sh:55 (server/ assets/ package.json package-lock.json client/lib/i18n.mjs client/locales/ scripts/install-server.sh); SHA256 в checksums; артефакт прикладывается к релизу. Однострочник установки: `curl -fsSL raw…/main/scripts/quick-setup.sh | sudo bash`.

**scripts/install-server.sh**: дописать в env-файл (env_kv-блок + merge_env_file, паттерн существующих) `ENOT_SECRET_KEY` и `ENOT_TRUSTED_PROXY` — разведка показала, что их не пишут (а main.mjs читает); значения приходят env-ом процесса (не argv — конвенция).

**compose.yaml**: проброс `ENOT_SECRET_KEY` (+ `ENOT_TRUSTED_PROXY`) в env сервиса enotdesk (для docker-режима мастера и 2FA/webhooks в docker-пути).

## T2. quick-setup.sh — интерактивный мастер (главная работа)

`scripts/quick-setup.sh`, режимы: bare-metal (дефолт), `--docker`, `--tarball <path>` (локальный файл, без скачивания), `--dry-run`, `--update` (перезапуск = обновление: те же вопросы, значения по умолчанию — из существующего env-файла), `--help`. Незаинтерактивные флаги для CI: `--domain --admin-login --admin-name --port --no-firewall --admin-password-stdin`.

Поток:
1. Preflight: root (self-sudo через sudo -E), ОС/порты, наличие curl; docker-режим — наличие docker compose.
2. **Вопросы (авто ru/en по $LANG, каждая строка — ru+en пара в msg-функции)**: домен (пусто = HTTP по IP + предупреждение; валидация hostname-regex как в install-server), логин админа (дефолт `admin`), имя (дефолт = логин), пароль (скрытый ввод ×2; **пустой Enter = автоген 20 символов, показать один раз в финале**; валидация ≥8/повтор), порт (8080), firewall (y/N).
3. Секреты — только автоген, никогда не спрашиваем и не echoing: `ENOT_TURN_SECRET`, `ENOT_SECRET_KEY` (openssl rand -hex 32, фолбэк /dev/urunal); `ENOT_TRUSTED_PROXY=127.0.0.1` когда включён локальный Caddy (per-IP лимиты за прокси работают).
4. Bare-metal: скачать `enotdesk-server.tar.gz` c Releases latest (curl -fsSL; `ENOT_SETUP_REPO`/`ENOT_SETUP_VERSION` оверрайды; **sha256-сверка по checksums-sha256.txt**) → распаковать install-server.sh → запустить его с env-переменными процесса (не argv!) → ждать health (curl ≤90с).
5. Docker: генерация .env (DOMAIN, TURN_SECRET, ENOT_SECRET_KEY) 0600 → `docker compose up -d` → health-wait → bootstrap в контейнере (`docker compose exec -T`).
6. **Админ без ручного ssh**: пайп 4 строк (login, name, password, password) в `runuser -u enotdesk -- env ENOT_DB=… node …/server/main.mjs bootstrap` (не-TTY ветка bootstrap.mjs уже существует); честные ошибки: exists / login_taken / слабый пароль.
7. Финал: URL-ы (/downloads, /operator), логин админа, пароль — только если автоген (один раз), предупреждение при HTTP, DNS-подсказка при домене, команды update/uninstall, подсказка smoke-remote.
8. Идемпотентность: обнаружение существующей установки → предложение `--update`; пароли/секреты никогда в argv, логах и ps.

## T3. CI-шаг + документация

- **test.yml** (ubuntu, блокирующий): `bash -n` обоих скриптов + `quick-setup.sh --dry-run --domain demo.example --admin-login boss --admin-name Boss --admin-password-stdin <<< 'Passw0rd-ex'` → grep разрешённых значений в плане (домен валидирован, пароль в плане НЕ отображается — ассерт маскировки). Shellcheck advisory (не блокирующий, если установлен).
- README (en+ru): секия «One-line install» с curl-командой; SERVER.md §0 «Быстрый старт мастером» (существующий ручной путь остаётся); MANUAL-QA: строка «quick-setup bare-metal + docker на чистой VM»; AGENTS.md: команда + pitfall (мастер не пишет секреты в argv; ENOT_SETUP_VERSION для пина версии).

## Исполнение и верификация

Два исполнителя параллельно (зоны: A = release.yml + install-server.sh + compose.yaml; B = quick-setup.sh + test.yml + docs) → ревью двумя ревьюерами (оси manifest/spec + craft: инъекции в промптах, утечка пароля в argv/логи/dry-run, идемпотентность, детерминизм CI-шага) → фиксы → `npm test` (335 не красный), lint, `bash -n`, локальный `--dry-run` обоих режимов, `docker compose config` → коммит, пуш. Живая установка на чистой VM — MANUAL-QA (честно помечаем).

## Осознанно не в v1

- Подпись curl-канала (репо публичное, TLS GitHub уже защищает канал; sha256-сверка тарболла добавлена).
- Unattended-массовая установка (preseed-файл) — следом, если понадобится.
- Интерактивный выбор «ставить лиTURN/TLS» — решается автоматически по наличию домена (флаги --no-turn/--no-tls установщика остаются для ручных случаев).
